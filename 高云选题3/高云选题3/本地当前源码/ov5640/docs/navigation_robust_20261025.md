# 自主导航弯道接管修复（2026-10-25）

本轮针对外圈转弯中途误停、内侧直角路口未转入、S 弯入口误报偏离三个问题。硬件源码仅修改 `vehicle_motion.v`、`vehicle_vision_fusion.v` 和 `vehicle_route_profile.v`。绕障、测距驱动、IMU 驱动、电机速度环、舵机标定和图像提取源码与本轮备份一致。

## 已复现的原因

1. 原接管条件等待两条边线都消失。实际弯道里，远处外边线碎片仍可能存在，但已经不能给出可靠道路中心。上一版在地图请求转向时仍保持零转角，或等到普通失视计数超时后停车。`sim/navigation_robust_old_failure.log` 记录了用上一版源码重新编译得到的失败。
2. 原偏离检查以车体坐标中的单个目标点横向距离和是否落到车后为依据。正常转弯、切换路径点时也可能满足这些条件，导致转弯状态尚未接上就报偏离。
3. 路口图像有时仍给出居中的直行道路，原视觉输出会抵消地图要求的转弯。
4. 路网圆弧连接处存在小于 1 mm 的量化接缝。它们不应定义新的切线方向；原计算会把极短接缝误认为突然转向。

## 当前控制行为

- 正常可见道路由视觉偏差、道路趋势和原 PD 控制居中，控制更新仍为 100 Hz，图像观测按相机实际帧更新。
- 当附近规划弯向、有效地图区段和路径跟踪转角共同确认转弯，并经过两帧完整图像确认后，使用地图与 IMU/编码器位姿闭环产生转向，叠加不超过 ±6° 的视觉修正，车轮总转角仍限于 ±28°。只有弯向提示本身不能覆盖正常直道视觉。
- 连续两帧完整图像无法给出有效中心，但地图附近区段仍有效时，进入受限地图接管。无需等待残留外边线完全消失，也不继续保持旧视觉转角。
- 接管期间仍不断更新位姿和路径点，S 弯两段按实际道路曲线改变转向；不把每一段 S 弯强制当作 90°。
- 地图接管后，双侧道路中心和趋势恢复可靠、且已接近规划出口方向时再交回视觉。这样不会把半转弯时看到的横向道路误当作出口。地图接管的出口航向容差为 10°；原独立盲转弯模式保留 3.5° 的出口条件。
- 自主视觉导航不再使用旧单点车体横向偏差直接判停。接管资格改用世界坐标下当前区段的横向距离、目标距离及前后位置检查；持续无效仍会停车。
- 启动时尚未获得有效道路仍原地等待，获得道路后再出发。终点截面停车、碰撞急停、传感器故障、编码器故障和堵转处理保留。

地图接管速度上限为 100 mm/s。接管不是无限失视前进：完整图像超过 200 ms 未更新、有效地图区段连续失效约 200 ms、反向行程超过 30 mm、单次接管超过 60 s 或 2400 mm 均会触发停止。地图区段的瞬时无效允许短暂消抖，避免路径 RAM 切换的一拍旧数据误停。地图区段横向条件使用 100 mm 乘区段的 Manhattan 长度，属于接管有效性边界，不代表道路或车身允许偏移 100 mm。

## 验证

数字验证共 53 次完整仿真运行：

- 21 次实际路网路线与独立车辆模型测试：外圈、内侧路口、双向 S 弯、截图整条路线；分别覆盖没有边线、残留单侧边线、双侧碎片但中心无效；另覆盖持续有效视觉、60/80 mm/s、S 弯出口接回视觉以及启动失视等待。
- 22 次原导航回归：左右 90° 弯、提前出现假出口、实际出口航向、起步摆歪、直线纠偏、终点停车等。
- 2 次接管状态测试，分别运行 RTL 和综合后的 Gowin 原语网表，覆盖 S 弯反向、视觉接回和时间/行程/图像/地图有效性边界。
- 3 次路径元数据测试，包含实际图中的 27 处极短或重复连接，以及综合后的 S 弯、90° 弯出口方向。
- 2 次截图路线测试：实际 RTL 规划器输出路径 RAM，再用它运行车辆闭环。路线长度 634 cm；RTL 输出 160 个点，与独立最短路校验去重后的几何逐点一致。
- 3 次视频、整车运动和路线参数回归，包含既有自主绕障和低速平滑停车。

完整截图路线闭环仿真的车头中心最大偏差约 21.72 mm。双向 S 弯增加出口后的直道测试，均确认视觉重新接回。短 S 弯测试若终点落在尚不可见的区域，可以保持受限接管直至终点；这些测试不宣称发生了视觉接回。

图像输入采用几何生成的观测和既有合成图像，不是对实车相机录像逐帧重放。车头中心误差也不等于整车车身保证不碰边。仍需实车检验轮胎打滑、IMU/编码器长期定位误差、真实视野和道路识别结果。

## 构建与交付

构建和审计由 `tools/build_navigation_robust_20261025.py`、`tools/verify_navigation_robust_build.py` 记录。位流位置为 `impl/pnr/ov5640.fs`，最终时间、SHA-256、资源和时序结果见 [本轮验证记录](navigation_robust_20261025_validation.json)。只有该记录成功生成后才视为完成构建验收。

本轮使用此前实测较快的普通综合与布局布线方式；此前增量匹配耗时更长，工程已有回退标记。本轮没有承诺固定保留其他模块的物理布线。备份保留于 `impl/baseline_navigation_robust_20261025/`，包括上一版源码、位流与验收记录。更早保存的物理检查点仍保留在原历史备份中。

首轮完整布线发现新增地图有效性判断直达转向限速器的组合链路不满足 33 MHz，最差建立时间裕量为 -0.716 ns。已在导航模块内对该判断增加一个系统时钟的寄存器边界，重新构建并重新运行受影响的闭环与整车回归。首轮失败的位流和时序报告保存于 `impl/navigation_robust_timing_attempt1/`，不作为验收版本。
