# 2026-10-24 绕障、相机与弯道修改

**2026-10-27 路宽后续更新：** 物理道路已实测为外圈373 mm、内圈/S弯340 mm。当前硬件扫描使用这两个宽度生成逐行投影范围和单边中心候选，路径几何不重生成。下列254/286 mm及车道扫描说明是该日期的历史验收记录，不代表本次视觉参数。

本文件区分源码行为、数字仿真、FPGA 构建与实车验证。构建结果见 `repair_20261024_validation.json`。

## 绕障

在真正触发绕障时依据最新侧向净空选择一次方向并锁存；触发前两侧均不可用仍平滑停车。启动后不因同一障碍重新选边、触发接近阶段急停或距离限速。编码器、IMU 持续失联、堵转、偏航、总行程和超时保护继续生效。

向外转弯和斜直行只消费已完成的障碍侧测距观测：记录有效局部最小值，回升超过 8 mm，连续两次有效回升，且最小值后行程至少 5 mm，即确认边缘。已经见到障碍后的连续无回波也可确认边缘；I2C 故障、未更新缓存和再次下降不能确认。边缘确认和车身侧向扫掠净空同时满足时立即回正，不再追加固定编码器直走距离。回升很早出现时仍保留车尾转动扫掠保护。

前激光离开障碍后的背景回波不再抬高障碍边缘投影；每次启动等三角函数结果有效后再采纳投影。较远的触发距离采用较浅的离开角（15/20/30/35°分档），避免固定 35°斜行过早产生很大横移。phase 3 回轨追踪器与完成条件保持原表达式。

## 路口与 S 弯

仍采用考虑全部剩余有序路径点的有向图最短路，不增加道路只能经过一次的约束。独立节点×路径点层 Dijkstra 比较实际 RTL 输出的完整代价，覆盖重复道路、最多八个中间点和既有照片坐标用例。

内部路口由两段相切圆弧连接：车头轨迹半径 65 / 315 mm，分角 50 / 40°。入口从原先约 239 mm 推迟至距路口 123.5 mm，出口距路口 225.7 mm。每个行驶方向单独生成，避免反向行驶把长出口变成提前入弯。完整瞬态自行车积分估计转向峰值低于保守 34°限值；这是短暂的车头轨迹半径，不能当成后轴持续转弯半径。

S 弯保留暂估 80 源图像像素半径，以两段反向圆弧直接相切，删除原来约 117 像素的中间斜线，并按源地图接近竖直的中间走向调整圆心。外圈采用此前已认可的源图曲线，外边界实测半径 376 mm 另行记录。

生成器逐段检查全部中心节点和边均位于源地图可通行区域。预览为 `road_centerlines.png`。**这不能证明完整车身不压线。** `tools/check_centerline_sweep.py` 使用真实 RTL 路线、连续后轴姿态和 320×200 mm 保守矩形车身额外检查；不会在每个圆弧重置车身朝向，也不会使用全局最小/最大偏移代替逐点安全检查。

**整车内弯余量尚未获得认证。** 源图路宽按现有全图比例换算与实测 254/286 mm 不一致，S 弯半径、转向连杆仍暂估。检查若发现源图占用重叠，会保留失败，不计为通过。当前中心线预览不能支持实车绝不会蹭边的承诺，构建成功也不能替代该项验证。
