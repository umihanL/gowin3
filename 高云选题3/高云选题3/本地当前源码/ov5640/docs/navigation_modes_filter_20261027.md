# 导航模式、高斯滤波与相机标定

本轮从已经生成宽路位流的工程修改。外圈373 mm、内圈/S弯340 mm；规划地图及中心线沿用当前工程。本轮完整构建、资源与时序以同名 validation.json 和 resource_usage.md 的最终结果为准。没有烧录或实车测试。

## 操作变化

“设置”底部新增“算法选择”，直接点击“惯性导航”或“惯导加视觉”，绿色为选中项。复位默认惯导加视觉，设置只保存在寄存器中；退出菜单保留，断电/复位恢复默认。每次进入导航时锁定算法，运行中不切换。

- 惯性导航：编码器计算距离，IMU和轮差融合航向，按既有地图路线跟踪。道路视觉的偏差、丢失、转弯恢复及斑马线限速不参与该模式的导航控制。相机预览仍可使用。
- 惯导加视觉：使用相同里程计与路线，在有效道路图像上接入视觉居中修正，地图/IMU处理已确认的弯道与出口交接。视觉不可用时退回地图/编码器/IMU跟踪，并将速度上限降为80 mm/s；重新获得可靠道路后恢复修正。

![设置页：惯导加视觉](settings_algorithm_fusion_20261027.png)

取消自主导航原来的三帧稳定判定、静止视觉位姿重置、等待预置转角稳定以及两秒起步倒计时。规划有效且IMU可用后，完成路线读取和初始航向计算即进入运行；仿真中8个10 ms控制周期内启动，不承诺按下触摸即机械瞬时运动。绕障/减速停车功能原有准备时间不变。

连续从其他自动功能切入导航时，上一功能可能仍有未完成的路径计算。准备阶段会等待它结束并重新请求当前路线首段计算，避免旧目标结果被丢弃后一直等不到当前目标。已覆盖8种不同切换时机；这属于计算流水的有限握手，不依赖视觉图像稳定。

屏幕不再显示V:TRACK、V:WAIT及同组视觉状态提示，IMU状态和S0提示保留。视觉丢失本身不再让普通道路导航停车。IMU超时、障碍物紧急停车、编码器异常、车轮无反馈、路线几何异常，以及已确认盲转的时间/角度/距离边界仍有效。

起步不再根据视觉自动修正地图初始位置和车头朝向。因此开始前应将实际车头中点与设置起点对应，并让车头大致沿第一段路线；不应把起步立即放行理解成已经自动完成放置姿态标定。

## 高斯滤波的位置和作用

道路识别采用如下顺序：完整原始帧 → 104×78 RGB222双缓冲缩略图 → 灰度3×3高斯 → 二值阈值 → 道路连续段/边线 → 分组稳健中心估计 → 逐行地面逆投影 → 横向及方向误差 → 时间滤波和转向控制。

高斯核为 `[1 2 1; 2 4 2; 1 2 1]/16`，对亮度先滤波再二值化；左右图像边缘复制延拓，扫描行不触及上下边缘。它复用现有图像RAM端口，在显示空白期间串行读出垂直三点，缓存两个垂直加权和完成水平卷积，不增加整帧缓存或乘法DSP。预览抢占读取时会重发扫描地址，避免把预览像素混入卷积。

滤波作用于导航道路识别。二值预览保留输入图像的直接阈值结果，便于判断光照和原始噪点，因此预览中的每个小点不一定随导航滤波消失。斑马线模块保留独立检测通道，纯惯导导航屏蔽其限速请求。

高斯降低细碎噪声，原有连续段约束和三行分组中值继续抑制孤立干扰。它不能消除大块阴影、反光、错误路宽、错误投影或错误分支；严重椒盐噪声还可考虑中值滤波。当前数字测试覆盖2%和5%像素翻转，不能据此保证任意实物噪声均被消除。

## 目前融合算法的真实含义

里程计在100 Hz控制节拍上用双轮增量估计位移和短时航向变化，IMU有效航向对轮差预测进行有限幅度的互补修正，再积分地图位置；未对加速度二次积分求距离。地图跟踪器使用车头坐标、规划目标和车辆几何计算转向。

视觉每帧扫描27行，使用现有相机投影表把道路中心转换成地面毫米。输出是车头前210 mm处的道路中心误差，以及按110 mm基线表示的道路方向斜率。融合控制器做时间低通、固定周期微分、受限横向积分和转向限幅/变化率限制。在有效普通道路上视觉具有居中控制权；规划选择路口分支并限定弯道入口，IMU支持看不见出口期间的航向控制。

本轮没有新增视觉到地图x/y的运行时观测更新，也没有实现EKF、通用VIO或SLAM。视觉目前主要纠正实际行驶方向和居中，不能保证同步消除地图里程计的位置漂移。取消起步视觉重置后，地图位姿初值由所选起点和第一段路线决定。仿真可以证明控制逻辑和指定模型下的行为，不能证明实车全程不压线。

## 为什么路宽增加，视觉反而可能变差

在中心线和车辆几何没有改变、道路沿两边等量拓宽的前提下，按原有路线行驶的几何容错增加。车宽200 mm时，内圈从254变为340 mm，直道居中静态单侧余量从27变为70 mm；外圈从286变为373 mm，余量从43变为86.5 mm。这些不是转弯时整车扫掠的保证余量。若只向一侧拓宽，道路中心会改变，旧路线就不再是新道路中心。

相机图像也随路宽改变。现有模型高度185 mm、车头后15 mm、左偏2 mm，以画面中心落在车头前380 mm推算有效俯角约25.10°；机械记录为30°。内参暂估fx=fy≈554.26、水平视场60°、畸变为0，尚未实际标定。

按这个暂估模型，车头前210 mm地面截面的可见横向范围约326 mm，比340/373 mm道路更窄。即使车大致居中，近处也可能看不全两边，迫使算法通过单边与路宽反推道路中心。相机高度、俯角、镜头畸变或宽度假设不准时，就会产生虚假的横向偏差。该数值是模型推算，不是实测镜头视野。

加高相机有可能改善覆盖，但也会改变每个像素对应的毫米数和可见近点，远处地面的投影误差尤其敏感。应先固定最终安装位置和镜头/图像模式，以实拍确认近、中范围两边界和必要弯道出口的可见性，再重新标定。逆透视无法补出画面外道路。

以下只按暂估60°水平视场和无畸变模型演示高度/俯角的耦合，前后偏移保持车头后15 mm；不是经过实测的安装建议。最近可见点按原始图像底边推算，导航有效扫描范围还会略远。

| 光心高度 | 有效向下俯角 | 底边最近地面距车头 | 前方210 mm处横向覆盖 |
| --- | --- | --- | --- |
| 185 mm | 25.10° | 约149 mm | 约326 mm |
| 250 mm | 25.10° | 约206 mm | 约358 mm，接近图像底边 |
| 280 mm | 25.10° | 约233 mm | 该距离已在图像下方、不可见 |
| 250 mm | 35° | 约139 mm | 约378 mm |

这解释了为什么只加高、不同步调整俯角未必有用。横向覆盖刚好大于路宽也不代表有足够偏移余量；还应留出车辆横移和转弯时边界移动的空间。

## 更适合下一阶段的融合方案

建议以编码器和陀螺/IMU预测统一位姿，再把视觉当作有置信度的测量，最后由同一个控制器跟踪路线。

1. 编码器提供短时距离，IMU提供转向变化，在100 Hz左右预测x、y、航向；保留速度/舵角闭环。
2. 经畸变校正和地面逆透视，在车辆坐标下拟合道路边线/中心线，提取相对已选路线的横向误差和航向误差。普通直道优先用双边，单边必须有可靠路宽；交叉口须先确认与规划分支的匹配。
3. 按帧完整性、新鲜度、边线连续性、路宽和拟合残差决定观测置信度；拒绝异常跳变。融合在行驶中逐步更新，起步不必等待视觉。
4. 现有FPGA资源紧张时先采用定点互补校正和查表；后续需要陀螺零偏/协方差估计时，可在合适算力上采用小状态EKF，如x、y、航向、陀螺零偏。应先解决标定和观测关联，再增加滤波器复杂度。
5. 长直道均匀边线主要约束横向和航向，不能独立确定沿路前后位置。需要匹配地图中的明确路口、曲线、已知地标，或跟踪多帧地面特征并补偿相机转动，才有足够信息修正纵向里程。

逆透视能在已标定、近似平坦地面上测出“当前画面地面点离车多远”。实际行驶路程需要多帧对应或已知地图地标；一张鸟瞰图本身不能直接给累计里程。坡道、桥面高度变化或车身俯仰会改变地面模型，需要另行处理。

## 加高相机后需要交付的参数

以车头中点地面投影为原点，X向前、Y向左，单位mm；图像使用原始640×480坐标，u向右、v向下。更完整步骤见[ipm测量清单](ipm_measurements_20261025.md)。

| 资料 | 要求 |
| --- | --- |
| 图像模式 | 原始分辨率、裁切/缩放、镜像/旋转、最终固定对焦；标定和运行完全一致。 |
| 相机外参 | 光心到地面的高度，相对车头的前后/左右偏移，光轴相对水平向下的俯角、左右偏航、横滚；记录哪些为估计值。 |
| 地面点对应 | 至少4个不共线点，建议9～12个覆盖近/中/远和左右；每点给X、Y、u、v，另留独立检查点。可在前方200/400/600 mm与左右100 mm布点，按实际视野调整。 |
| 镜头内参与畸变 | fx、fy、cx、cy和k1、k2、p1、p2、k3及模型；或15～20张不同位置/角度的清晰棋盘格原图，注明内角点数量和方格实际边长。 |
| 道路/地图 | 确认外圈373 mm、内圈/S弯340 mm，确认是否对称拓宽及中心线是否移动；中心线弯曲半径和地图地标实际位置。 |
| 里程/车辆校验 | 轮径、每轮一圈编码计数、实际直行已知距离对应计数、左右差异；车宽/轴距及舵机中位、左右轮角。没有变动的结构尺寸无需重复测量。 |

地面对应点足够准确时可以直接拟合单应矩阵，不必依赖手量的精确俯角；明显镜头畸变仍需先校正。建议同时提供居中、左右偏30 mm、左右偏航约5°的原始图像，标明实际姿态，用独立点验证毫米误差。

可直接填写[地面标记CSV模板](ipm_ground_points_template.csv)：fit用于拟合，validate单独验证。模板距离只作布点建议，按最终相机的实际视野调整；u/v必须从同一固定姿态下的原始帧读取，不能估填。也可以只提供可辨认编号的原始帧和对应实测X/Y，后续再从原图读取像素。
