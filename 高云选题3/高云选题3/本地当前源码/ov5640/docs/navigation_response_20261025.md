# 自主导航响应与弯道丢线修复（2026-10-25）

本次仅修改 `src/vehicle/vehicle_motion.v` 和 `src/vehicle/vehicle_vision_fusion.v` 两个硬件源码文件。自主绕障、回归原轨迹、测距、IMU、速度环、舵机标定、图像采样和道路提取源码均保持原样。构建脚本另增加增量布局布线选项。未烧录、未实车验证。

## 起步为何先走再纠正

旧版在准备阶段已经获取视觉误差并生成 `vision_steer`，但没有把这个命令输出到实际的 `steer_deg`；只有进入运行状态并收到跟踪器结果后才应用。再叠加原有视觉输出与实际舵机变化率限制，会出现启动后先直行、随后才打角的现象。

新版在停车准备阶段就将有效视觉转向送入原有舵机链路，保留既有平滑限速，不改动共用舵机驱动。视觉命令连续稳定约 120 ms 后才允许起步。静止打角本身不能把阿克曼车身转正，但可以使车辆从开始行驶时就产生正确方向的纠偏。未获取有效视觉仍保持不启动。

## 弯道为何直接报偏离

旧版要求连续两帧同方向单边丢线后，才接受两帧双边丢线。实际画面可能跳过单边阶段，或路线弯向被“规划切线与车头相差超过 12°”这个额外条件压住，于是丢线计时到达后直接停车。原有单边阶段还可能被导航的普通追点偏离条件抢先终止。

新版使用规划曲线的方向标签提供弯向，不再等车头或规划切线已经偏出 12°。图像里的实际道路仍决定普通转向，单有规划弯向不能让可见直道打满。最近约 1.2 秒的有效弯向会被记忆，包括有效画面中的方向趋势。

保留“内侧边线先消失时限角沿外侧跟随”的行为；如果采样跳过这个阶段，连续两帧完整图像均没有边线、此前已取得道路且有新鲜明确的弯向，也允许受限转弯。交替丢边、残缺图像、无弯向的普通丢线、终点附近均不能据此触发盲转。单边弯道引导也计入正常路线推进，避免普通追点偏离检测抢先停车。

重新看到出口且通过持续有效性检查后回到视觉控制。原有 28° 最大车轮转角，以及 100° 航向、800 mm 行程、8 秒失视上限保留。不依赖编码器必须先走完某个指定距离才允许转弯。

## 增量布局布线

本机 Gowin V1.9.12.03 随附的 SUG100 用户指南第 41～42 页、SUG1220 Tcl 指南第 44 页确认：Arora V 支持以 `.pr` 复用布局和布线，Tcl 为 `set_option -inc_pnr <file>`。本轮显式使用修改前备份 `impl/baseline_navigation_20261025/impl/pnr/ov5640.pr`，防止生成过程中覆盖基线。

本轮确实启用并尝试增量 PnR，但匹配阶段长时间停留、内存不断增加，920.860 秒后主动终止，已超过上一轮全量约 775.575 秒，未得到可交付结果。不能声称本轮增量加速成功。已保留尝试日志并直接复用本轮完成的综合结果，转为普通布局布线，省去第二次综合。

`impl/incremental_pnr_slow.flag` 记录此次退化；`build.tcl` 默认遇到此标志使用普通布局布线。通过环境变量 `GOWIN_INCREMENTAL_PR` 显式指定时仍可尝试增量。增量不是只重编译一个 Verilog 文件，也不保证其他模块每条线都不变化。最终方式、耗时、资源及时序以验证记录为准。

## 验证

先用旧源码复现“跳过单边画面不会转弯”和“启动前没有准备转向”两项失败，再运行新源码。导航专项包含 14 次运行：新的边界事件检查、PD 独立车辆收敛、既有丢线限制、左右弯各含正常与跳过单边阶段、0/±8° 初始偏航、四种终点路线组合。另运行真实生成图像帧扫描到融合控制器、原有整车运动回归、独立综合的融合控制器 Gowin 原语仿真，共 17 次通过。

完整结果以 `navigation_response_20261025_validation.json` 为准。合成图像和独立车辆模型不是用户照片的精确标定，也不能替代实车测试。

## 逆透视准备

完整测量步骤见 [逆透视标定清单](ipm_measurements_20261025.md)。本次沿用当前镜头安装与图像域算法，没有把尚未测得的 35° 参数写进代码。改变俯角后必须重新标定；逆透视不能恢复画面之外的道路。
