# 导航视觉位置修正与路口方向约束（2026-10-27）

本轮只修改自主导航及其道路观测接线。完整路线按照片坐标重建为 284 个采样点、约 976 cm：起点 `(327,201)`，途经 `(327,253)`、`(181,293)`、`(25,241)`、`(179,177)`、`(247,233)`，终点 `(327,163)`；屏幕纵坐标转换为内部地图的 `319-y`。

## 修改内容

1. **视觉参与修正转弯位置。** 从现有逆透视提取实际观测到的近、远两个地面道路点，和当前执行点附近的规划线段配准。弯道的两个不同方向提供前后位置约束，逐帧修正地图位置：沿车头方向每次最多 10 mm，横向每次最多 3 mm。编码器和 IMU 继续预测运动；视觉修正不清空编码器、不重置航向，也不改变累计行程。
2. **直道继续以视觉居中，转弯入口采用修正后位置。** 入口前同时控制入弯前的航向和横向偏差；看到远处弯道不等于立即到达转向位置。图像中路口变宽的暗色块保留边界证据，但不再把它的重心当作道路中心。定位使用最远不超过 450 mm 的可靠地面带，控制 PD 仍使用原来的较近地面带。
3. **确认的直角路口保持选定方向。** 当约 90° 路口刚开始转入时，禁止与规划方向相反的追踪命令。后续 S 弯仍允许必要的反向修正，没有把所有弯道强制锁成固定方向或固定 90°。
4. **每个实际接受的新弯道独立计恢复行程。** 完整路线测试发现多个弯道共用首个恢复计数，可能在后面的 S 弯触发行程保护；现在到达新的入口事件后重新计数。摄像头新鲜度、持续失配和出口恢复上限仍有效。
5. **启动歪放保留视觉航向校准。** 原先“附近有未来弯道就屏蔽启动对齐”的条件过宽。现在只在近处道路误差小于 16 mm、又有临近未来弯道时保留歧义保护；近处明显偏移时仍进行启动航向与横向校准。独立模型中左右各歪 8° 的旧逻辑最大车头中心误差为约 176/205 mm，修正实验降为约 13/27 mm；最终源码还需通过正式回归，最终数字以验收 JSON 为准。

新模块 `vehicle_visual_localizer.v` 使用共享乘法器、串行除法和已有路径 RAM；通过地址仲裁与导航读取交替运行，没有增加第二套图像或路径 RAM。

## 验证边界

- 纯直道没有前后位置特征，无法仅凭两条平行道路边线知道起点前后放偏了多少；弯道等几何特征进入视野后才能修正这个偏差。本轮实测的是模拟起点前后各 60 mm，不能推成任意距离都能恢复。
- 原几何摄像头模型没有复现标记路口完整的“右转变左转”，复现了转入前的相反方向修正和后续恢复误停。方向约束与路口观测过滤有独立测试，但实车错选分支的唯一根因尚未证实。
- 轨迹最大误差统计指**车头中心**。地图与实物比例尚未完整标定；不能用这个数值声称整段车身和全部车轮均在道路内。车身矩形或轮廓在当前名义地图上的扫掠检查也不是实车道路净空的验收结论。
- 相机焦距等内参仍沿用现有估计。未烧录、未做实车验证；真实照明、遮挡和相机安装变化仍需现场检验。
- 绕障算法、驱动、舵机标定、道路规划 ROM 和上位机通信源码保留；本轮没有冻结其他模块的物理布局布线。之前增量匹配比普通方式慢，因此沿用已有普通实现流程，实际构建耗时写入验收记录。

完整上一个发布版快照位于 `impl/baseline_navigation_visual_20261027/`。第一次构建因补测发现启动歪放问题而中止，其输入、精确旧 motion 源码、网表、日志和失败测试保留在 `impl/navigation_visual_20261027_attempt1/`，不会作为最终下载版本。
