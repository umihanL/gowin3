# 拓展任务分工与斑马线开关修订（2026-10-29启动，10-30验收）

本页优先于同日之前的 [拓展任务说明](extension_tasks_20261029.md) 和 2026-10-28 斑马线限速说明。本轮仅本地源码与仿真，未烧录；沿用已确认的 Gowin 许可缺失结论，不重复构建，不生成或冒充新版位流。

## 现在两个拓展入口做什么

“拓展1视觉识别”：用于 X5 的火焰、人物、消防员等视觉任务。对话不再属于拓展1。

“拓展2对话控制”：用于 X5 麦克风对话、场景分析、语义导航和灭火指令。

FPGA 的这两个按钮**确实有本地动作**：切换到通信控制来源并进入驾驶页，保持电机停止，显示“上位机选择任务”。它们目前不会通知 X5 开启 YOLO 或麦克风，也不自动调用某个 X5 任务；先从 X5 上位机选择拓展2并开启收音，随后才可在拓展2内下达语音任务命令；拓展1不收普通语音，不能靠对着未启用的麦克风切换任务，停车使用上位机按钮。这不是双向任务启动接口，避免用户以为按下 FPGA 屏幕后板端模型已启用。

## 斑马线默认关闭，导航彻底不再限速

- 删除 `vehicle_motion.v` 中所有斑马线半速、最高60mm/s及斑马线额外减速斜坡。自主导航即使看到斑马线且检测开关开启，也保持其自身正常目标速度和路线控制。
- 切换到通信驾驶页后，右侧有“斑马线检测 开启／关闭”按钮。默认关闭，实际停稳后才可修改。行驶或等待制动完成时按钮不可更改。
- 开关输出直接连接 `vision_video` 内的真实 `vision_zebra` 检测器。关闭会清空白条/黑条计数、采样状态和 detected/update，不只是隐藏画面提示。重开要等到下一完整新帧，不接受开关前的残留半帧。
- 只有**明确交通任务＋开关开启**才会发现斑马线后停车。普通视觉、对话、定距运动和地图导航都不会被斑马线触发交通停车。
- 关闭状态下交通启动命令被拒绝。等待红绿灯时关闭开关，小车继续停止；重新开启也不会自动走，仍需明确绿灯指令。已消费的同一条斑马线保持锁定，连续10帧确认离开后才能触发下一条。

## 新协议

沿用固定10字节 UART，原协议其他命令保持。

| 项目 | 内容 |
|---|---|
| `0x17` | D0=0关闭／1开启；D1～D3必须为0。仅停稳可变更，不改变任务模式。 |
| `0x97` | D0=0接受、1不在通信控制页面、2参数错误、4尚在运动／制动。ACK后读取14确认实际值。 |
| `0x14` 回复flags | D1 bit4表示真实 `zebra_enable`；其他bit定义保留。 |
| `0x15` 能力 | D2 bit4=1表示支持这个开关。本轮完整能力字节为 `0x1F`。 |
| `0x03` 交通启动 | task_mode=3且开关关闭时返回结果3，保持停车。 |
| `0x13` 绿灯 | 必须task_mode=3、WAIT_LIGHT且开关开启；否则不放行。 |

本地触摸和 UART 修改同一寄存器，因此上位机能看到本地按钮的实际变化。若两者同周期发生，UART17优先，以后续14回读为准。开关只在整机复位时恢复默认off；普通任务切换保留选择，但切换本身不会启动交通任务。

## 代码与验收

实际链路：

```text
FPGA 触摸按钮 / UART 0x17
              ↓ 停稳校验
vehicle_extension.zebra_enable（唯一状态）
        ├─→ 14状态 bit4 / 屏幕显示
        └─→ 顶层 → vision_video → vision_zebra.enable
                                    ↓ 有效完整帧
              仅 task_mode=3 → 制动 → 停稳 → WAIT_LIGHT → X5 红绿灯
```
