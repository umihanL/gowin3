## 结论

1. 选择“惯性导航”后，位姿推算来自双轮编码器和IMU，不使用摄像头观测；视觉转向、视觉限速和斑马线请求被屏蔽。视觉模块仍运行不等于视觉参与控制。
2. 普通路径跟踪确实读取规划器的执行RAM；本轮四类实际RTL规划输出及闭环执行未发现路线倒序、显示/执行点不一致或地图Y轴翻转错误。
3. **最终转向不只受IMU、编码器和地图影响。侧向ToF避让和前向ToF触发的自动绕障，在纯惯导模式仍然有效。两者都已经复现出右转覆盖地图指令。**
4. 因此，不能把现有模式理解成“无论ToF读到什么，都严格沿规划路线运行”。也不能仅根据一瞬间的舵角符号，断定路线分支走错；该控制器允许闭环纠偏和S弯交接中的短暂反打。

## 确认的问题一：ToF侧向避让可覆盖地图转向

代码：`src/vehicle/vehicle_motion.v:238` 至 `:248`。

```verilog
wire signed [15:0] route_candidate=
    tracker_steer<8 && tracker_steer > -8 && close_left!=close_right ?
    (close_left ? -16'sd3 : 16'sd3) : tracker_steer;
```

`close_left/close_right` 指对应侧面ToF诊断正常、数据未超时、读数在0～100 mm之间。这段逻辑直接替换地图跟踪器输出，且不检查 `fusion_selected`。

按工程约定正舵角为左转、负舵角为右转。只要地图输出在-8°与+8°之间，单侧近物就能使它改成固定的另一方向。它也没有要求车辆此时位于直道。

定向仿真实际输出：

```text
pure=1 vision=0 mapSteer=1 output=-3 left=50 right=1500
pure=1 vision=0 mapSteer=-1 output=3 left=1500 right=50
```

这证明纯惯导中确实存在“地图要求左转，实际命令右转”的分支。真实外圈左弯基线的第302个控制周期，规划曲率为左、目标仍在前方100 mm、地图输出左1°；因此该条件也适用于左弯入口的小舵角阶段。定向复现没有声称实车当时的ToF一定读到了50 mm。

现有 `route_steer` 的方向约束只在 `forward_mm<0` 时将某些反向命令归零；目标还在前方时，上面的覆盖仍会生效。

## 确认的问题二：纯惯导仍可能转入自动绕障

代码：`vehicle_motion.v:664` 附近触发绕障，`:685` 附近使用 `bypass_steer` 接管转向。

导航模式9与独立绕障模式8共用此逻辑。正常导航、未进入绕障/回归、车轮小舵角累计达到15个控制周期后，前方存在已知障碍且距离不大于设置的触发距离，就可能进入绕障。默认触发距离650 mm。绕行方向按前方左右命中及侧向空间选择；本次两侧空间相等时选择右绕。

定向仿真采用纯惯导、视觉屏蔽、规划为向东直线：

```text
front=500 left=1500 right=1500 output=-28 phase=1
```

即前方读数500 mm、两侧均1500 mm时，自动右绕接管并输出右28°。该覆盖无需视觉，也不要求规划路径本身向右拐。

实车若看到明显的大角度右拐，此分支比固定右3°的侧向避让更符合指令幅度；缺少当时的测距、模式阶段和位姿记录，不能确定实车一定由它触发。

## 规划到执行的数据链

```text
nav_road_planner.route[]
  → execution_x_q8 / execution_y_q8 / execution_lock
  → vehicle_subsystem 的 profile/motion 共用读取端口
  → vehicle_motion 按 route_index 读取目标
  → vehicle_odometry 用编码器与IMU估计车头位姿
  → vehicle_tracker 用目标相对车辆的位置计算转向
  → ToF侧向覆盖 / 视觉选择 / 绕障仲裁
  → 舵角限幅、变化率限制、舵机映射和差速
```

规划器输出正序样本，绘制路线的连续点与执行RAM同一次写入；执行坐标为地图厘米Q8。运动模块转换为毫米：

```text
X_mm = map_x_q8 × 10 / 256
Y_mm = 3200 − map_y_q8 × 10 / 256
```

地图Y向下、里程计Y向上，此处翻转正确。跟踪器采用 `lateral = dy*cos − dx*sin`，左侧目标为正，正转向经当前舵机映射对应左转，与用户确认的手动/遥控左转正常一致。运行中并非按菜单显示的左右轮圈数开环执行；那些数值是路线统计，实际控制是位姿闭环追踪目标点。

选择纯惯导后，`fusion_selected=0`，`visual_navigation=0`，`navigation_steer=route_steer`；视觉不再选择转向。编码器平均增量提供距离、右轮减左轮增量提供短时航向预测；IMU观测以互补修正更新航向。没有加速度二次积分求距离。

初始地图位置取路径第一个点，初始地图航向取第一段路线的方向；IMU相对角在该方向上建立零参考。因此车辆仍须实际放在相应起点并对准第一段路线。手动舵机方向正常并不能单独证明IMU安装轴向、航向符号、左右编码器归属和计数比例都正确。

额外把外圈左弯的所有视觉输入替换为持续有效但严重错误的道路偏差、方向、路口和斑马线信号。纯惯导输出的完整逐周期记录与无视觉基线逐字节相同。这一结果针对该闭环测试及当前源码，不等于实车路线精度承诺。

S弯及多弯路线确实出现了局部舵角与当前前视目标的曲率标签相反的区间，但仍按规划到达。前视目标提前约60 mm推进，而且控制参考点是后轴前219 mm的车头；车身航向与车头运动方向不同，曲率标签不能直接当成此刻车轮必须保持的符号。不能把这类反打与ToF直接接管混为一谈，也不应靠全局交换左右舵机符号处理。

## 后续修复应当采用的边界

若希望“纯惯导”严格按规划验证，建议屏蔽该模式的侧向ToF主动打舵；前方障碍处理先停车，或明确规定允许绕障时才偏离路线，保留紧急停车、IMU/编码器故障和失速保护。融合模式及独立绕障功能可各自保留需要的逻辑。

若只要求避免反向拐入错误分支，应在确认到达实际弯道入口后约束转弯交接，并保留合法的出弯纠偏；不能简单规定“规划曲率为左时，所有右舵一律禁止”。安装与里程标定应在同一符号约定下核验，不能因为手动转向正常就直接改IMU符号。

本轮未做上述行为修改。硬件源码哈希、默认位流及具名位流仍与已验证版本一致；资源占用未变化：Logic 53409/59904，CLS 28572/29952，BSRAM 113/118，DSP 88/118。
