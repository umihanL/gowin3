# 编号点位导航（2026-10-31）

本页的编号点功能已于2026-10-31合入现有UART拓展工程，X5九点语音、ROS 2和EXE上位机接入及离线联动检查也已完成；本轮X5修改尚未部署到实板、未实机验收。以 [合并版使用说明](地图编号导航与无线演示.md) 为准。定位、跟踪与转向继续使用IMU＋编码器和规划路径；普通导航不再使用斑马线限速，斑马线仅用于明确启用的独立交通任务。

## 操作流程

1. 在设置的控制模式中选“通信模式”。
2. 将车放在已知编号点并核对朝向，在EXE上位机选择并确认实际起点。口头说一个起点不算实际位置确认；若说“从1号点到3号点”，起点必须与已确认值一致。
3. 地瓜派收到语音或HMI编号目标后，唯一`extension_task`桥先发送20 SET_START上传确认的起点，再发送08 SELECT_POINT。FPGA自动设置终点、清除旧途经点并规划起点至该终点的路径；用户画的禁行区域仍然生效。
4. 查询 09 POINT_STATUS，直到状态为 2，表示路径与执行轮廓都准备好。
5. 地瓜派发送原有 03 START，D0=1。屏幕自动切换到自主导航运行界面，小车开始执行路径。
6. 地瓜派每 500 ms 发送心跳，接收完成/失败消息。超过 2 s 没有有效通信会停车，恢复心跳不会自行起步，必须明确发送恢复命令。

选点只规划，不会提前动车。正式EXE／语音流程由`extension_task`完成上传起点、选点、查询、启动和心跳，不另开串口客户端。其到达判断需要本轮任务关联、运行见证、F0和随后实际停稳反馈；ACK仅表示命令被接收。独立调试客户端仍可使用`Client.navigate_to(3, task=1)`，或依次调用`select_point`、`wait_point_ready`、`start_navigation`，但不能与ROS串口桥同时占用端口。独立客户端／纯FPGA触摸屏调试时仍可在“自主导航 → 路径设置”手动设置实际起点。

## 串口扩展

帧格式不变：A5 5A 01 SEQ CMD D0 D1 D2 D3 CHECK。CHECK 是第 2～8 字节异或，115200 baud / 8N1 / 3.3 V TTL，E13=FPGA RX、E14=FPGA TX，共地。每次等 ACK 后再发下一条，不能把整批命令连续塞入串口。

| 命令 | D0 | D1 | D2 | D3 |
| --- | --- | --- | --- | --- |
| 08 选点并规划 | 点号 1～9 | 任务号 0～255 | 0 | 0 |
| 09 查询编号点状态 | 0 | 0 | 0 | 0 |
| 03 开始已规划导航 | 1 | 任务号 0～255 | 0 | 0 |
| 05 停止/暂停 | 0 | 0 | 0 | 0 |

任务号用于追踪完成事件，与目标点编号是两个字段。同一任务建议使用相同任务号。03 不含新点号，执行的是已准备好的路径。

88 ACK 成功载荷为 result, point, 1, task。result=0 表示已受理规划，不代表规划成功。失败 ACK 沿用原错误格式。

89 查询回复为 0, selected_point, state, error：

- state=0：没有可执行的编号路径，或路径被编辑作废。
- state=1：规划中或执行轮廓准备中。
- state=2：可发送 START。
- state=3：规划失败/取消，error 为原规划错误码，STOP 取消为 3。
- state=4：已进入导航会话，运动/暂停/完成详情用原 06 查询。

错误码：1=页面或控制源不适合，2=参数错误，3=起点或路径尚未准备好，4=忙，5=未知命令。08 只接受通信模式的路径设置页，必须有起点且当前未在规划。运行时不接受修改终点，防止执行路径被替换。

规划时 05 会取消规划并使路径失效。运行时 05 保留位置和执行进度，用原 07 恢复。退出运行页/切换控制模式会解除运行会话。完成发送 F0、失败 F1、通信超时 F2；这些表示 FPGA 状态，不能代替实车位置验证。

## 地瓜派接入

tools/host_serial_client.py 提供 select_point、point_status、wait_point_ready、start_navigation、navigate_to。tools/diguapi_navigation.py 提供 VoiceNavigator，供 AI 工具函数传入整数点号，并串行处理请求、维护心跳。无需在 FPGA 上运行语言模型。

Python 示例：

    import serial
    from diguapi_navigation import VoiceNavigator
    with serial.Serial('/dev/serial/by-id/替换为FPGA独立USB串口', 115200, timeout=0.05, write_timeout=1) as port:
        with VoiceNavigator(port) as navigator:
            navigator.navigate_to(3, task=1)
            result = navigator.wait_until_done(timeout=180)
            # 或分两次语音：select_point(3, task=1)，之后 start(task=1)
            # 其他线程可调用 stop() / resume()
            # events 是完成/故障事件队列。

命令行：python tools/host_serial_client.py --port COM8 navigate-to 3 --task 1 --watch。Linux 替换为实际 UART 设备。--watch 维持心跳直到完成/失败/超时，Ctrl+C 发送 STOP。

X5的ROS、语音和上位机代码位于相邻`RDKX5_消防小车系统`目录。九点目标已接入现有EXE和语音任务路由，使用唯一`extension_task`串口桥；`numbered_navigation.py`负责确认起点、规划／启动与到达核验，`mission_node.py`处理到达后的任务切换。编号限定为1～9，编号点不自动等于楼栋号。完成的是本地代码和离线联动，本轮尚未部署到X5，也未做实车验收。

到达后，拓展1使用`manual`策略进入`inspect`，保持YOLO观察，等待用户主动问场景或对话，不自动调用Qwen。拓展2使用`scan`策略，只在已停车、安装确认、执行器及实际角度反馈就绪时扫描找火；发现火焰后等待用户选择编号，完成瞄准后还须单独请求喷水。缺执行器／反馈显示等待就绪，途中丢失停车或反馈则停止扫描。`scan`不能授权自动喷水，也不映射成原`auto`模式。

YOLO在非交通任务中保持开启，不因到达重启。红绿灯仍由独立交通任务启用。电脑与X5可以连接同一个热点，EXE服务地址仍为`http://<X5无线IP>:8090`，YOLO预览仍为8086；无线替代电脑网线，不替代X5与FPGA之间的UART。UART引脚及波特率沿用[合并版无线与接线说明](地图编号导航与无线演示.md)。
