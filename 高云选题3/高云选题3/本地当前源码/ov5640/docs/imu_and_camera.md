# LSM6DSV16X 接线、校零与全视场摄像头

适用工程：当前目录的 `ov5640.gprj`。

## 接线

连接 **主 SPI 接口**，不要接模块上的辅助 OIS SPI 接口。约束已经写入 `src/ov5640_ddr3_tft.cst`，无需自己再分配。

本表已按当前 CST 更新。旧版文档中的 A13/A14/A15/A16 分配已失效；请使用下表。

| 模块端 | 开发板扩展口信号 | FPGA 球位 | 顶层端口 |
| --- | --- | --- | --- |
| SCLK / SCK / SPC（主接口） | GPIO0_3 | A16 | IMU_SCLK |
| MOSI / SDI / SDA（主接口） | GPIO0_5 | A19 | IMU_MOSI |
| MISO / SDO / SA0（主接口） | GPIO0_7 | F14 | IMU_MISO |
| CS / CS_N（主接口） | GPIO0_1 | A14 | IMU_CS_N |
| VCC | 3.3V 电源 | — | — |
| GND | GND | — | — |

**GPIO0 所在电压选择必须设置为 3.3V**，约束文件不能代替板上的电压跳线。以上 GPIO0 编号是信号编号，不是排针物理脚序。按开发板接口丝印/引脚表对应接线；模块和 FPGA 必须共地。INT1/INT2 不使用，轮询 FIFO 即可。这里针对用户的 3.3V 模块供电，不能将裸芯片引脚直接接到 5V。

当前信号分配以 `src/ov5640_ddr3_tft.cst` 为准，球位与 GPIO0 信号编号对应关系依据 ACG720-138&60K 通用管脚分配表。**S4=B21**、**S0=F15**。IMU 使用 GPIO0_1/3/5/7；PS2 使用 GPIO0_0/2/4/6。若模块将串行输出标成 AD0，请先按该模块原理图确认它对应主接口 SDO/SA0，不要连接 SDO_Aux。

屏幕上的 `ID ERR` 表示读取主寄存器页的 `WHO_AM_I(0x0F)` 时未得到预期的 `0x70`；它不是姿态校零错误，也不能仅凭这条状态判断模块损坏。当前正常界面没有显示失败时实际读回的 ID 字节。S0 只重新校零，无法解决身份读取失败。

## 操作

1. 接好模块、编译下载，保持模块静止。启动期间显示 `INIT` / `WAIT`，有效姿态数据到达后显示 `WARM`。
2. 有效样本累计约 2 秒供融合稳定，再静止约 1 秒建立零姿态。完成后显示 `IMU:RUN`，三个角度从零开始。计算完成后即显示有效角度，无需等校零完成；`WARM` / `MOVE` / `ZERO` 阶段的角度以芯片融合坐标为参考，`RUN` 才表示已切换为用户零位。
3. **S0：仅重新校零**。`S0: REZERO` 就是“按 S0 重新校零”的操作提示，不是错误码。原来 `S0:ZERO` 也是此意。按一下后将模块放稳约 3 秒，视频和触摸继续运行。
4. **S4：整个工程复位**。摄像头、DDR、触摸、IMU 全部重新初始化，返回主菜单并清除用户路径设置，姿态自动重新校零。松手稳定 20ms 后才解除复位。
5. 现在将旧版统一的 `CAL` / `OFF` 拆成明确状态，出错后自动重试；没有有效数据或断连时显示短横线，不把旧角度当作有效测量。

| 状态 | 含义 |
| --- | --- |
| INIT / WAIT | 初始化 / 等待第一组姿态数据 |
| WARM | 收到了姿态数据，正在等待融合稳定 |
| MOVE | 移动量超过校零条件；请按 `HOLD STILL` 提示放稳 |
| ZERO | 正在采集零位，保持静止约 1 秒 |
| RUN | 已完成校零，显示相对零位角度 |
| ID ERR | 芯片标识读取失败，检查 SPI 接线、3.3V 与共地 |
| CFGERR | 配置回读不一致，包括 SFLP 嵌入页 |
| NO DAT | 配置后未收到姿态数据，或正常运行后数据中断 |
| FIFO | FIFO 溢出，程序先局部清空 FIFO 并恢复输出，不立即重启融合引擎 |

错误状态在自动重试期间保留，收到有效数据后恢复，避免错误只闪过一瞬。初次等待数据超时为 5 秒，正常运行后超时为 2 秒。

2026-10-20 恢复逻辑更新：全 1 的 FIFO 状态按轮询周期局部重读，连续异常不再三次就触发全局复位；已有 2 秒有效样本看门狗仍保留。FIFO 溢出仅切旁路/连续模式清 FIFO，保留 SFLP 与用户零参考。短暂离线标记角度不可用，但不清零位；实际 SW_POR 通过 fusion_reset 触发重新校零。导航使用已校准更新，短断流由左右编码器差分预测航向，恢复时每 10 ms 修正不超过 0.5°，异常单帧大跳变丢弃；持续 1.5 秒无有效姿态仍停车。回归覆盖连续八次坏状态恢复及转弯中 700 ms 断流。软件不能修复虚焊、断电或信号完整性问题；换模块仍掉帧且轻压有效时，应检查焊点、连接器和供电，重新焊接并固定短导线有助排除机械接触不良。

### CFGERR 的进一步定位

`CFGERR` 表示芯片 ID 读取得到 0x70，但至少一个配置寄存器的必要字段回读不正确。它不能独自证明模块损坏，也不能证明所有 SPI 接线都可靠。S0 只影响姿态校零，无法解决配置回读失败。

普通配置写入后等待 100µs，只比较需要使用的持久字段；第一次不匹配后再延时读两次，连续三次不匹配才报告 CFGERR。写入值仍遵守手册的保留位要求。寄存器切页使用下述独立的重试与实际页面验证。量程、数据率、FIFO、SFLP 使能等必要位都保留校验。

报错时原来三行角度的位置显示：

```text
IMU: CFGERR
REG: 5E
SET: 53
GOT: 43
M:38 I:08
```

以上仅为格式示例，**不是当前硬件读到的值**。所有数值均为十六进制：REG 是出错地址，SET 是期望值（普通配置为完整写入值，页面探测为期望字段值），GOT 是实际读回值，M 是比较掩码，I 是配置步骤。上述示例表示 SFLP 输出数据率没有写成预期值。错误信息在重试期间保持，到有效数据恢复后退出显示。

配置步骤对应：00=IF_CFG，01=CTRL3，02=陀螺仪量程，03=加速度量程，04=FIFO 清空，05/06=加速度/陀螺仪数据率，07=切嵌入页，08=SFLP 数据率，09=SFLP FIFO，0A=切主寄存器页，0B=切嵌入页，0C=SFLP 使能，0D=切主页，0E=FIFO 连续模式。

### 实物反馈 REG:01 SET:80 GOT:00 M:C0 I:07

这组数据来自用户实物：第 07 步向 `FUNC_CFG_ACCESS(0x01)` 写 `0x80`，三次读回的最后一次为 `0x00`。`M:C0` 表示检查 bit7/bit6 的寄存器页选择。前面 00～06 步配置已通过，但尚未完成 SFLP 配置，因而还没有姿态数据可供校零。`0x80` 与手册及 ST 驱动的嵌入页选择定义一致。

这组数据能确定**切页验证失败**，不能单独区分“写入未生效”和“页面已切换、选择位回读异常”，也不能据此断言芯片损坏或 SPI 时序错误。旧代码只重复读取选择位，随后全局复位；如果每次初始化的首次切页都丢失，便会一直循环，无法在本轮初始化内恢复。

本版修正：

1. 加速度、陀螺仪启动后先等待 100ms，再首次访问嵌入页。原来的这段等待位于第一次嵌入页配置之后。
2. 切页按 ST 驱动的方式先读再修改选择位，保留无关持久控制位，不重放自清零的 `SW_POR`。每次切页后等待 1ms。
3. 读取选择位后再核对两处实际页面内容。嵌入页检查 `SFLP_ODR(0x5E)` 的数据率字段以及未启用的 `FSM_INT2(0x0F)=0`；主页检查 `WHO_AM_I(0x0F)=0x70` 及 `CTRL3` 的 BDU/IF_INC。首次进入嵌入页期待复位默认 120Hz（掩码 0x38 下为 0x18），第二次进入期待已设置的 60Hz（0x10）。依据为 DS13510 Rev4 p52、p121、p128、p139。
4. 页面内容不符合时，在当前初始化中重新读改写切页，最多尝试三次。始终无法确认目标页则保持 CFGERR，绝不向未验证的页面写 SFLP 配置。选择位读回异常但两个页面检查均通过时，可以继续；后续 SFLP 配置仍逐项回读，且只有收到有效姿态样本才会置 online。

如果选择位与实际页面都不符，仍显示 REG:01；若选择位看似正确但实际页面不符，则显示出错的页面探测地址，例如 REG:5E、SET:18、M:38、I:07。这里 SET:18 是探测的期望字段，**不是要向 0x5E 写入 0x18**。

新增的六种 SPI 仿真包含正常芯片、注入选择位回读异常、每次复位后的首次切页写入丢失、全部切页写入丢失、假成功的选择位回读、无法返回主页。后五项是故障注入，不能当作实物芯片行为已经得到证实。旧版在前两类可恢复故障下失败，新版通过；真实模块是否恢复仍需下载本版确认。

校零期间检测角速度、加速度模长以及姿态变化。明显移动或自由落体时不接受零位，连续静止计数重新开始。不必严格水平放置：保存的是完整参考四元数，任意静止姿态均可作为三轴零位。

文字位于横屏视频右上角，字体 10×14 像素。**背景透明，没有黑色矩形和边框**；RotX 为黄色、RotY 为青色、RotZ 为橙色。仅字符边缘保留 1 像素黑色阴影以便在亮背景上辨认。文字之间仍显示摄像头原图。本版采用 640×480 原比例横屏视频，左右各 80 像素黑边，菜单使用方法见 [navigation.md](navigation.md)。

- 当前屏幕 `RotX`：相对零位旋转向量的 X 分量，原第一通道。
- 当前屏幕 `RotY`：相对零位旋转向量的 Y 分量，原 Pitch 通道。
- 当前屏幕 `RotZ`：相对零位旋转向量的 Z 分量，原第三通道。

当前屏幕按用户选择使用**四元数旋转向量**，说明见下节；当前七路串口的前三路为标准 Roll/Pitch/Yaw，便于绑定 VOFA 欧拉控件，导航内部仍使用原来的 ZYX 航向角。ZYX 欧拉角中，Pitch 只有 −90°～+90°，越过 90° 会折返，并伴随 Roll/Yaw 分支切换；接近奇异位置时，很小的非 Y 轴转动也可能使 Roll/Yaw 大幅变化。显示单位为度，一位小数是显示分辨率，并非承诺 0.1°测量精度。轴向以校零时模块的 X/Y/Z 为准。

### 跨越 ±90° 的三轴旋转角（当前版）

新增 `src/imu/imu_rotation_vector.v`，接收 `imu_attitude.v` 已计算的完整相对四元数，输出旋转向量 `theta * axis`。其中 `theta = 2*atan2(length(q.xyz),q.w)`，先选取 `w>=0` 的等价四元数，再将角度按旋转轴方向分配到 X/Y/Z。使用一个平方乘法器、一个分量乘法器和逐拍除法器，三个通道同时提交；正常 60Hz 样本间隔内完成，不增加地图 ROM。

纯绕 Y 轴时输出例如 `(0,89,0) → (0,90,0) → (0,91,0) → (0,120,0)`，反向同样成立。三个数是同一个旋转向量的分量，**复合旋转时不再是标准 Roll/Pitch/Yaw 顺序欧拉角**。旋转向量模长为从零位到当前姿态的最短转角，范围 0～180°；经过 180° 仍有正负分支边界，不表示累计旋转圈数。90° 不再是奇异位置。

导航继续接收原 `imu_yaw`；新的 RotZ 不送入导航航向闭环。SPI 驱动、传感器融合配置、S0 校零条件以及所有引脚均沿用当前版本。

“返回原位置偏约 10°”需区分表示问题与测量问题：新显示链路直接由当前相对四元数计算，不进行角速度积分、不累计跨界修正、不根据静止状态自动归零。给定与初始零位相同的输入，即使中间多次正反翻转，也应返回零；若传感器输出本身偏转，程序会保留该偏差。当前没有实物四元数往返记录，不能将实物约 10° 偏差全部断言为旧欧拉角转换造成，也不能承诺替换显示表示就能消除传感器融合漂移或掉线重校零。

新增 3264 组端到端仿真，以实际 binary16 压缩输入的独立浮点结果作参考，计算误差限制为 0.3°：包括四种任意零位、X/Y/Z 正反转到 150° 后返回、跨 ±90°、转轴偏离 Y 轴 9°、返回原输入无累计偏差、保留真实 10° 输入偏差，以及额外的 ±180° 端点、等价 q/-q、微小角度和掉线恢复测试。输入压缩本身的不确定性不计入 FPGA 算术误差，更不是实物精度承诺。

### Pitch 接近 90° 的数值修正（2026-10-17）

旧版 Pitch 使用 `atan2(s, sqrt(1-s*s))`，其中 `s=2*(w*y-x*z)`。四元数经过 binary16 输入、Q14 重建和相对姿态乘法后，模长会有少量取整误差；公式中的常数 1 使这类误差在接近 ±90° 时被放大。理想 +90° 输入在单位校零姿态下显示 +89.5°，在 `(Roll=20°, Pitch=-25°, Yaw=35°)` 校零姿态下显示约 +88.8°，已用修正前 RTL 仿真复现。

现改为 `atan2(2*(w*y-x*z), sqrt(R32*R32+R33*R33))`，其中 `R32=2*(w*x+y*z)`、`R33=w*w+z*z-x*x-y*y`，分子和分母采用同一四元数的尺度。R32/R33 从 Q28 缩到 Q14 后，分两个时钟复用一个 16 位平方乘法器；补回尺度后送入原有平方根单元。没有强制将某个角度区间显示为 90°。SPI 驱动、校零条件和引脚保持原配置。

该历史修正保留于内部欧拉角解算。原有仿真覆盖 8 种零位参考、376 次旋转，Pitch 测试包括 ±89.5°、±89.9°、±90° 及越过 ±90° 后的欧拉角折返，Pitch 扫描误差要求为 0.3° 以内；另检查 Roll 可经过 ±90° 到达 ±180°，正常旋转保留 RUN 校准状态。当前屏幕使用上一节的旋转向量，七路串口使用标准欧拉角。这是给定四元数的计算验证，不是对实物模块精度的保证。接触导致的 `ID ERR`、掉线重校零仍需单独排查。

LSM6DSV16X 没有磁力计，Yaw 是**相对航向**，不是地理方位角，长期仍可能缓慢漂移。按 S0 可重新设零。

## 晃动后偏差与全姿态显示

用户确认 VOFA 三维控件使用 **Roll/Pitch/Yaw 欧拉角**。历史三路串口是 **RotX/RotY/RotZ 旋转向量**，两种表示在复合旋转时不能互换，直接绑定会使模型方向不正确；这属于显示链路问题，不能用来断言传感器漂移。当前按用户要求总共发送七路：前三路为匹配欧拉控件的 Roll/Pitch/Yaw，后四路为两电机的目标与实测速度。

工程读取芯片内 SFLP 六轴融合后的四元数，并非 FPGA 对原始角速度简单累加。用户提供的 `LSM6DSV16X.pdf`（DS13510 Rev4）第 8 页列出：静态 Pitch/Roll 精度 1.5°、低动态 Pitch/Roll 0.5°、高动态 Pitch 1.6°/Roll 1.2°；Yaw 列出静态 0.5°/5 min、低动态 0.7°/5 min、高动态 5.9°/5 min。这些是手册列出的性能，不能替代当前模块、温度、安装与运动条件下的实测，也不能承诺修改显示算法后达到这些数值。

晃动会引入线加速度，加速度计暂时无法将它和重力完全区分；温漂、陀螺仪残余零偏、振动和实际回位姿态不一致也可能产生偏差。只说“小幅翻转几次后有 1～2°”尚不能确认哪一项为主因。当前六轴数据没有磁力计或其他绝对航向参考，Yaw 长期漂移无法仅用重力消除。上次修复角度表示并未调整 SFLP 内部融合或改善真实零偏，本次也不通过自动归零隐藏测量偏差。

完整四元数可用于任意空间姿态，包括倒置。标准欧拉角在 Pitch=±90° 时没有唯一分解，数字分支切换无法在所有姿态都消除；三维模型直接使用归一化四元数则没有此表示奇异性。旋转向量在 180° 仍有分支边界，不应要求三个数值同时全空间无跳变。任意姿态的表示能力不等于任意运动下都没有测量误差。

另一个精度限制是 SFLP FIFO 只提供 binary16 的四元数 XYZ，FPGA 重建 W。纯绕 Y 轴的理想 178° 输入，其 Y=sin(89°) 压缩后可能直接变成 1.0，重建会得到 180°。这是压缩量化示例，并非实板漂移记录；换四元数显示能修正控件表示不匹配，却不能恢复传感器未传出的精度。

操作与量化方法：

1. 把模块固定在刚性底座上，先静置 30～60 秒，再按 S0，等待 RUN；不要拿手持大致回位作为精度基准。
2. 使用下节的正确通道绑定，当前欧拉控件使用第 1～3 个通道（索引 0/1/2）。欧拉角在 ±90° 的分支限制仍然存在；当前七路帧不输出四元数。
3. 记录开始与结束都保持同一物理基准姿态至少 20 帧，中间再翻转。全过程确认没有离开 RUN；重新校零会改变参考，记录不可混作同一次往返。
4. 如果需要减少实际偏差，应先用这种固定基准记录确认静态漂移、运动后恢复以及各轴差异，再决定零偏/温度/加速度六面标定或外部航向约束。没有原始测量依据，不把加强显示低通滤波当成精度提升。

历史工具 [三维姿态查看页面](imu_pose_viewer.html) 用于旧十通道四元数记录，也兼容旧三通道旋转向量；**不支持当前七路帧**。当前工程请使用 VOFA 并按下节绑定通道。页面没有插值平滑、自动归零或偏差抵消。

旧十通道记录可运行 `python tools/analyze_imu_pose.py 记录文件.txt`；这个历史脚本不支持当前七路帧。它比较最前与最后各 20 帧的平均四元数，报告三维姿态差和窗口抖动，不用欧拉角相减。它只能测量输入姿态差；端点必须确实回到同一物理基准，不能自动断定所有差值都是传感器漂移。

## 七路姿态角与电机速度串口输出（FireWater）

独立模块 `src/imu/imu_firewater_tx.v` 复用现有 `uart_byte_tx.v` 发送器，在同一帧输出三轴欧拉角和四路电机速度，总共七路。引脚继续使用 **M15**，3.3V TTL；连接 USB 转串口模块的 RX，并共地。串口设置为 **115200 波特率、8 数据位、无校验、1 停止位、无流控**，VOFA+ 选择 **FireWater** 协议。

| 通道索引（从 0 开始） | 数据 | 单位/格式 |
| --- | --- | --- |
| 0 / 1 / 2 | 标准 ZYX Roll / Pitch / Yaw | 度，一位小数 |
| 3 | M1 目标速度 | mm/s，有符号整数 |
| 4 | M1 实测速度 | mm/s，有符号整数 |
| 5 | M2 目标速度 | mm/s，有符号整数 |
| 6 | M2 实测速度 | mm/s，有符号整数 |

**VOFA 欧拉角三维控件：Roll 绑定索引 0、Pitch 绑定索引 1、Yaw 绑定索引 2，单位选择度。** 如果界面通道从 1 编号，对应第 1、2、3 个通道。速度曲线绑定索引 3/4/5/6。目标速度为现有后轮差速计算之后传给各电机闭环的命令；反馈直接取原编码器测速结果。

例如 IMU 暂不可用、仍有电机速度数据时：

```text
samples:0.0,0.0,0.0,200,187,75,69\r\n
```

这里的 `\r\n` 表示实际的回车、换行字节（0x0D、0x0A），不是四个可见字符。每 **50 ms** 同时锁存七个数值，发送 **20 帧/秒**，不依赖 IMU 样本脉冲。IMU 尚未输出有效数据或掉线时，前三路发 `0.0,0.0,0.0`，电机速度继续更新；恢复后发送当前角度。一帧内输入变化不改变已锁存的内容。零角度占位不代表姿态测量有效，请同时查看屏幕 RUN/错误状态。

屏幕继续使用旋转向量，串口前三路为标准欧拉角；导航原航向输入不变。`WARM / MOVE / ZERO` 时参考芯片融合坐标，`RUN` 后参考用户校零姿态，按 S0 重新校零也会改变串口的零位。模块参数 `CLK_HZ / BAUD / SEND_HZ` 当前顶层为 `33000000 / 115200 / 20`，`EXTENDED_POSE=0、MOTOR_TELEMETRY=1` 选择本次七路输出。原三路/十路兼容模式保留于模块及回归测试，当前顶层不启用。格式转换使用逐拍 BCD 运算，无需新增 FIFO、DSP 或 ROM。

## 实现和寄存器依据

依据用户提供的 `LSM6DSV16X.pdf`（DS13510 Rev4）：SPI 协议 p24～26，ID p64，量程与数据率 p65～71，FIFO p75/110～111，SFLP p8/123/131/139/142。

LSM6DSV16X 原始寄存器输出的是角速度/加速度。工程启用芯片内的 **SFLP 六轴融合**，其中包含陀螺仪零偏估计；FPGA 读取融合后的四元数，执行参考姿态变换、平方根和 CORDIC 反三角运算，得到屏幕上的姿态角。

主 SPI 为 mode 3（CPOL=1、CPHA=1）、MSB first，33MHz 时钟下 **250kHz**，为杜邦线接线增加时序余量。CS 在一整次突发读期间保持低电平。WHO_AM_I 应为 `0x70`。先恢复用户页，再按 ST 官方例程使用 `FUNC_CFG_ACCESS.SW_POR`（0x01=0x04）进行全局复位并等待 100ms。

先启动加速度和陀螺仪，以同一个 60Hz 数据率运行并等待 100ms，再确认嵌入页、配置 SFLP、使能融合及开启 FIFO。每项持久配置都回读校验，实际寄存器页也交叉检查，不能仅凭 WHO_AM_I 和三个主控寄存器判断姿态流正常。`online` 仅在首组有效四元数和原始六轴数据读出后置位。

比对依据：[ST 官方 sensor_fusion 示例](https://github.com/STMicroelectronics/STMems_Standard_C_drivers/blob/master/lsm6dsv16x_STdC/examples/lsm6dsv16x_sensor_fusion.c) 和 [ST 官方寄存器驱动](https://github.com/STMicroelectronics/lsm6dsv16x-pid/blob/master/lsm6dsv16x_reg.c) 中的 `lsm6dsv16x_sw_por`、`lsm6dsv16x_sflp_game_rotation_set`。FPGA 没有逐字移植这些 C 文件；它使用上述寄存器协议实现状态机。

| 寄存器 | 写值 | 用途 |
| --- | --- | --- |
| 用户页 0x03 | 0x01 | 关闭 I²C/I3C，保持四线 SPI |
| 用户页 0x12 | 0x44 | BDU、连续地址读 |
| 用户页 0x15 | 0x04 | 陀螺仪 ±2000°/s |
| 用户页 0x17 | 0x01 | 加速度 ±4g |
| 0x01 | 0x80 / 0x00 | 嵌入页 / 用户页 |
| 嵌入页 0x5E | 0x53 | SFLP 60Hz，保留位按手册写入 |
| 嵌入页 0x44 | 0x02 | 四元数进入 FIFO |
| 嵌入页 0x04 | 0x02 | 传感器运行并稳定后使能 SFLP |
| 用户页 0x0A | 0x06 | 连续 FIFO |
| 用户页 0x10 / 0x11 | 0x05 / 0x05 | 加速度、陀螺仪 60Hz 高性能模式，与 SFLP 一致 |

从 0x78 连读 TAG + 6 字节，识别 TAG_SENSOR=0x13。XYZ 是小端 binary16 格式，重建 `w=sqrt(max(0,1-x²-y²-z²))`。读 0x22～0x2D 原始六轴用于静止判断。FIFO 满/溢出先局部清 FIFO 并恢复流；短暂坏状态不清零位，只有真正融合重启才清零参考。

本次反馈暴露了上一版的可观测性和校零问题：配置成功就显示 `CAL`，但是否真正收到数据没有独立状态；超时重启会清空校零进度，出现 `CAL` 和 `OFF` 循环。校零还直接要求未补偿的原始角速度小于约 1.96°/s、姿态分量变化小于 128，原始零偏和微动都可能使计数反复清零。现在使用 6°/s 原始角速度门限、0.85g～1.15g 模长和完整姿态稳定窗口联合判断，静止窗口缩短为 1 秒；处理 `q` 与 `-q` 等价，避免跨 180°时被误认为大幅运动。仍拒绝明显旋转和自由落体。实物未采到 SPI 波形，因此不能把某个初始化差异断言为这块模块的唯一原因。

`src/imu/lsm6dsv16x_spi.v` 管理配置与轮询；`spi_register.v` 产生 SPI 波形；`imu_attitude.v` 管理校零和姿态变换；`imu_math.v` 为多周期算术；`attitude_overlay.v` 绘制文字；`board_buttons.v` 处理按键。

## 摄像头为什么只看到一小块

旧初始化表沿用 720p 配置：Y 输入窗口为 250～1705，且 `0x5001=0x83`，其中 bit5 的 ISP 缩放未开启。输出被单独改成 482×362 后，不能得到完整传感器区域的等比例缩略图。

现在依据本地模块包内 `OV5640_自动对焦照相模组应用指南(DVP_接口)__R2.13C.pdf` §4.1.2（p19～20），使用完整 4:3 预览窗口和配套的 binning、PLL、HTS/VTS：

- 输入窗口：X=0～2623，Y=4～1947；含传感器边缘余量，按官方预览模式配置。
- X/Y increment=0x31，垂直 binning 使能。
- HTS=1896、VTS=984，曝光上限同步调整。
- `0x5001=0xA3`，开启 ISP 缩放。
- 输出仍为 482×362；3×3 高斯处理裁掉四周各 1 像素，显示 480×360。

缩放位的定义见 `OV5640_CSP3_DS_2.01_Ruisipusheng.pdf` §5.1/5.9。模块用户手册也区分了输入窗口、预缩放偏移和输出大小。

这样扩大的是**参与取景的传感器区域**，不是屏幕窗口或芯片物理面积。最终视角仍受镜头限制。沿用工程的 25MHz 摄像头 XCLK，官方 24MHz / 30fps 预览参数对应的名义帧率约 31.25fps；实际帧率还受自动曝光影响。
