# 上下位机通信框架

## 使用入口与引脚

设置 → 模式选择 → **通信模式**。手动、遥控、通信三个控制来源互斥。复位默认仍为手动、停止。

| 信号 | FPGA 引脚 | 连接 |
| --- | --- | --- |
| `host_tx` | E14 | 接上位机串口 RX |
| `host_rx` | E13 | 接上位机串口 TX |
| GND | 板上 GND | 上下位机共地 |

独立串口默认 **115200 波特、8 数据位、无校验、1 停止位、无流控**，3.3V TTL 电平。原 M15 的 VOFA 七通道调试输出保留。RS-232 电平需要转换器。

通信模式下，在原驾驶页可以启动直行；触摸前进/转向和 PS2 驾驶不会取得控制权。在已规划路线的导航运行页可以启动导航，进入页面本身不会自动启动车辆。

## 帧格式

固定 10 字节二进制帧：

```text
A5 5A 01 SEQ CMD D0 D1 D2 D3 CHECK
```

`SEQ` 为上位机自选的 8 位序号，回复原样带回；`CHECK = 01 XOR SEQ XOR CMD XOR D0 XOR D1 XOR D2 XOR D3`，帧头不参与校验。多字节数值均为小端。帧中断超过 20ms、版本错误、校验错误或停止位错误时丢弃，重新寻找帧头。

**请求采用逐条发送、等待回复的方式。** 收到前一回复再发下一命令。忙时普通控制命令返回 BUSY，不执行；STOP 在忙时仍立即生效，随后补发回复。回复只表示命令已接收/设置，不等于车辆已机械停稳或任务完成。接收校验无效帧不回复。

## 已接入命令

| CMD | 功能 | 数据 | 生效条件 |
| --- | --- | --- | --- |
| `01` | 心跳/握手 | D0～D3=0 | 可查询状态；运行中定期发送 |
| `02` | 设置目标速度 | D0/D1=0～1000 mm/s，D2/D3=0 | 通信模式驾驶或导航运行页 |
| `03` | 启动任务 | D0=0 直行 / 1 已规划导航；D1=任务号；D2/D3=0 | 直行需驾驶页；导航需导航运行页、路线和预处理就绪 |
| `04` | 减速/调整速度 | 与 `02` 相同 | 速度经过现有控制斜坡；设 0 可降到零，恢复需另发速度值 |
| `05` | 停车/暂停导航 | D0～D3=0 | 驾驶停止；导航保留路线进度、位置和转弯状态，并接入制动 |
| `06` | 查询状态 | D0～D3=0 | 返回状态与标志 |
| `07` | 继续导航 | D0～D3=0 | 仅继续未结束的已启动导航，不重置起点 |

启动不自带速度值，先发送 `02`，再发送 `03`。直行始终保持零目标转角；转向、倒车、路径上传及复杂业务指令留给后续扩展。通信模式导航仍受原自主导航速度上限、弯道及斑马线限速约束，发送 1000 不会绕过这些上限。

通信目标速度由串口 `02`/`04` 单独维护，复位初值 200 mm/s；设置页原有速度值不会覆盖它。上位机用设置速度的回复或状态标志确认自己的控制流程。

默认 **2 秒没有收到有效控制/心跳帧就停车**，上位机建议每 500ms 发一次 `01`。恢复通信只恢复连接状态，不会自动重启；直行需重新 `03`，暂停中的导航需 `07`。离开控制页面、切换控制模式、上电或复位均撤销启动状态。心跳和速度设置不能自行启动。

## 回复与事件

普通回复 `CMD = 请求 CMD OR 80`，SEQ 与请求相同。

- `81` / `86`：D0=0，D1=`阶段[7:4] | 运动状态[3:0]`，D2=FLAGS，D3=任务号。
- 其他回复：D0=结果码，D1=FLAGS，D2/D3=目标速度；成功的设置速度回复回显此次设置值。
- 结果码：0 成功，1 当前模式/页面不允许，2 参数越界，3 任务/路线未就绪或已结束，4 忙/任务已启动，5 未定义命令。
- FLAGS：bit0 通信模式，bit1 在可控制页面，bit2 已启动且未暂停，bit3 导航会话选定，bit4 连接有效。其余为 0。bit3 在完成后保留以显示完成状态，不代表车辆运行。
- 运动状态：0 等待，1 启动准备，2 运行，3 完成，4 传感器故障，5 受阻，6 跟踪故障，7 路线错误，8 编码器故障，9 车轮无反馈。

异步事件使用同样帧格式，SEQ=0：

| CMD | 事件 | D0 | D1/D2 | D3 |
| --- | --- | --- | --- | --- |
| `F0` | 导航完成 | 任务号 | 状态码 3 | 0 |
| `F1` | 导航失败 | 任务号 | 实际故障状态码 | 0 |
| `F2` | 连接超时停车 | 任务号 | 原因码 1 | 0 |

导航只有到达终点并报告状态 3 才发送 F0，STOP 或命令 ACK 不伪装成任务完成。任务结束后需退出并重新进入导航运行页才能启动下一次导航，防止完成状态被立即重启覆盖。

`vehicle_host_link` 另提供 `event_valid/event_code/event_value` 接口用于后续业务完成回报，目前整车中该通用业务接口未接任务源。它有一个待发事件槽；主机应持续读取事件，后续若需要事件确认、重传、多任务队列、序号去重，应在该模块继续扩展。当前协议无认证、无应用层重传，不能把它当作已完成的完整业务协议。

## 发送示例

```text
设置速度 100 mm/s：A5 5A 01 01 02 64 00 00 00 66
启动直行，任务 1：A5 5A 01 02 03 00 01 00 00 01
停车：           A5 5A 01 03 05 00 00 00 00 07
```

上位机示例：`tools/host_serial_client.py`。Python 需要另行安装 pyserial；脚本不会在导入时打开串口。例：

```powershell
python tools/host_serial_client.py --port COM8 speed 100
python tools/host_serial_client.py --port COM8 start-drive --task 1 --watch
python tools/host_serial_client.py --port COM8 stop
python tools/host_serial_client.py --port COM8 start-nav --task 2 --watch
python tools/host_serial_client.py --port COM8 resume --watch
```

`--watch` 持续接收事件并每 500ms 发送心跳，Ctrl+C 时尽力发 STOP；不使用 `--watch` 的启动指令在 2 秒无后续通信后按看门狗停车。更换 COM 号或引脚连接前，请按实际设备设置。


## 2026-11-01 语义区域导航与 FPGA 地图界面

- `0x30` 的能力字节（回复第 3 个参数）新增 bit 5。它同时表示下面的 `0x3A`、`0x3B`、`0x25` 和任意目标路线启动能力。
- `0x3A START_REFERENCE`：请求 4 个参数为 0。回复 `BA x_cell y_cell heading_lo heading_hi`（仍按标准帧包裹）；x/y 是 **2 cm 图像规划网格**，中心为 `20*cell+10` mm；角度为有符号 int16、0.1°，向右 0、向上 +900。起点或 IMU 参考无效时 x/y 都为 `FF`。起点是屏幕或主机明确设置的参考，不是自动定位结果。
- `0x3B START_EDIT_GENERATION`：请求参数全 0，回复 `BB` 携带 32 位小端触屏起点编辑序号。上电为 0；仅物理触屏成功设置起点、点击原起点旋转方向时递增，溢出跳过 0；主机 `20/24` 不递增。即便起点/IMU暂时无效，合法查询仍返回已存的物理编辑序号，避免主机重设参考后误判新触屏；有效性单独由 `3A` 的 `FF FF` 判定。读取采用 `3B → 3A → 3B`，序号一致且非 0 才接受；任务执行后消费该序号，避免把上次任务起点当成当前位置。同位置同方向重新摆车也需再次触屏确认。
- `0x25 RESET_NAV`：参数全 0。必须在主机控制范围内，`run=0`、两轮实测速度在 ±5 mm/s 内持续 100 ms、B13 泵输出为低，且没有拓展移动/规划工作时接受。成功回复 `A5`，首参数为 0。它结束旧路线会话、回地图页并清除旧路线，不移动、不重置当前惯导位置。随后发送 `20 SET_START`、`24 SET_START_HEADING`、`22 SET_GOAL`、`23 PLAN`，等待路线及速度曲线就绪后发送 `03 START(mode=1, task_id)`。
- `PLAN` 完成只发布就绪路线，不隐式启动。任意目标 `SET_GOAL 0x22` 规划的路线也可以启动，不再要求有 1～9 的目的点编号。禁止靠路点编号伪造区域语义。
- `STOP 0x05` 仍然保留原路线、姿态和会话；`RESUME 0x07` 仍在原路线继续。只有显式 `RESET_NAV 0x25` 才取消旧会话。新路线应先保存停稳时的 `31/32/33` 姿态快照，再重置和规划。
- **坐标区别**：`0x32` 惯导姿态为物理 mm，X 右、Y 上；`0x35` 路线和 `0x3A` 起点网格为图像坐标，X 右、Y 下。地图高 3200 mm，转换使用 `image_y = 3200 - pose_y`。

本地触屏：选“起点”，第一次在道路上点击后默认箭头沿该位置的有效道路切线（包括弧线）；请根据实际车头核对。再次点击同一起点箭头（约 ±8 像素范围），每次逆时针转 90°，四次恢复原方向。按住不连转；改变方向会使旧规划失效。箭头方向与 IMU 的相对变化一起进入实际路径规划，不只是装饰图标。

自主导航运行页显示地图、目标、惯导位置/方向和停车按钮，不再叠加摄像头或测距传感器面板。绿色箭头按编码器＋IMU 的估计位置移动；显示朝向量化为 8 方向，控制角度保持原精度。已走路线按真实惯导位置后方 4 cm 范围逐步擦除，静止不会随时间继续消失；到达后清除剩余显示路线。擦除只改显示位图，不更改实际执行采样、UART 路线下载或暂停恢复状态。惯导漂移仍会反映为地图位置误差，显示不是绝对定位。


全局道路规划现已使用真正的正向 A*：扫描优先级为 `f=g+h`，启发函数是到目标触达区域的曼哈顿下界 `max(0, L1_q8-goal_radius)>>9`。ROM 坐标是 cm Q8；实际 1764 个节点、1800 条有向边均满足 `L1_delta <= 512*edge_cost`，因此启发项不会高估到目标区域的最短代价，并满足一致性。路径松弛仍使用真实 `g`，终止比较最小 `f` 与当前完整候选代价；多中间航点的反向后缀动态规划保持 Dijkstra。车头方向过滤、道路曲线采样、惯导执行和停车约束沿用原设计。

## 2026-11-03 弯道再规划与区域内优先

新增 `0x26 SET_REGION_PREFERENCE`，能力查询 `0x30` 的 flags **bit 6** 表示支持：

| 参数 | 含义 |
| --- | --- |
| D0、D1 | 区域左上角 `x0_cell, y0_cell` |
| D2、D3 | 区域右下角 `x1_cell, y1_cell` |
| 全部为 `FF` | 清除区域偏好 |

坐标为 2 cm 图像网格，X 向右、Y 向下，边界包含在区域内。要求 `0≤x0≤x1≤175`、`0≤y0≤y1≤159`；非法范围返回 2。命令采用普通 `A6` 回复：D0 为结果码、D1 为 FLAGS、D2/D3 为目标速度，不回显矩形。必须先等待本次序号的成功 ACK。车辆已停稳、B13 已关且没有移动或规划任务时才接受，不会启动小车。

搜索腿的顺序为：读取实际停稳姿态 → `25 RESET_NAV` → `26 设置区域` → `20 设置当前起点` → `24 设置实际车头方向` → `22 设置下一搜索点` → `23 PLAN` → 等待就绪 → `03 START`。进入区域和最后驶向出口的腿使用 `26 FF FF FF FF`。`SET_START` 保留刚设置的偏好；`RESET_NAV`、切换拓展模式、普通编号点选择、触屏操作或离开主机控制会清除它，避免影响下一个手工任务。

区域偏好是一项道路代价：区内边使用原长度；从区外节点出发的边使用 `33×原长度`，即增加 32 倍区外惩罚。不会穿越地图中没有的道路，也不会硬裁剪合法绕行。X5 的搜索顺序使用同一代价；FPGA 显示的路线厘米数仍累计真实边长度，不把惩罚分数当距离。反向中间航点规划按原有向边的起点计算惩罚，保持与正向规划一致。下面的连续任务方式代替逐检查点重置导航。

弯道停车的量化坐标可能离一条直线分支更近，而实际车头沿另一条圆弧。规划器先尝试原来的精确最近坐标；若该腿无可达路线，再尝试原始起点 **曼哈顿距离 6 cm 内**、与实际车头切线偏差不超过 **35°** 的多个前向节点。前向判定只容许 2 cm 的网格取整后向误差。它不改写实际车头方向、不开放反向别名，也不允许在距离很远的另一条道路重新起步。

当前点已经落在目标的 6 cm 到达窗内时，可能只生成一个采样点；该情况仍返回规划错误 1，不伪造导航完成。X5 应把真实停稳的近处检查点作为观察站处理，或选择下一个非退化的导航腿。只有真实的任务到达事件才作为完成证据。

本地验证入口：`sim/run_corner_region_planner.py`，覆盖弯道起点、反向拒绝、区域权重、真实长度及多航点反向代价；`sim/run_semantic_navigation.py semantic_touch_preflight_tb semantic_navigation_tb host_patrol_pause_tb` 覆盖 UART 设置与原有暂停流程。测试不发串口、不移动硬件。

## 连续多检查点任务与执行目标快照

任务开始时发送一次 `25 RESET_NAV`、`26 区域偏好`、`20 起点`、`24 实际朝向`，依次发送 `21 WAYPOINT(x_cell,y_cell,0,0)`（最多 8 个），然后 `22 出口目标`、`23 PLAN`。所有检查点、出口及前后道路方向在同一次 FPGA 规划中确定。等待完整路线下载核对后，用一次 `03 START` 开始。中间检查点仅约束路线，不停车、不增加检查点限速；正常弯道限速保留。识别到稳定火焰时才用 `05 STOP` 暂停，处理完并回到暂停位置后用 `07 RESUME` 沿原路线继续，保留同一任务号、路线代次和惯导参考。

`0x30` 能力字节 bit 7 表示支持 `0x37 NAVIGATION_TARGET_SNAPSHOT`。读取顺序是 `31 → 32 → 33 → 37`，后三条请求均为同一 `pose_token`（D0/D1，小端），D2/D3 必须为 0。`31` 同时锁存姿态、航向、路线代次和当前执行目标索引。`37` 回复 `B7`：

| 字节 | 含义 |
| --- | --- |
| D0/D1 | 路线代次 generation，uint16 小端，与下载全路线的 `34` 对照 |
| D2/D3 | `navigation_target_index`，uint16 小端，范围 0～2047 |

无效/旧 token、无有效姿态、目标索引超出路线、正在规划、路线失效或代次改变，均返回 `FF FF FF FF`。读查询不会刷新驾驶看门狗。发送缓冲忙时也可能返回该无效标记，主机重新取一组完整快照，不能把它当作到达或恢复命令。

`navigation_target_index` 是惯导跟踪器**正在追踪的前瞻目标**，不等于车身已通过的点。检查点停靠仍须结合真实姿态、同向道路、过弯后的直线距离和连续航向稳定判定；索引用于排除路线交叉处的错误匹配。地图坐标继续表示原来的车头参考点，不能直接改成车身中心。当前 `vehicle_config.vh` 的车头到后轴为 256 mm、车身长 320 mm，清尾距离不能只使用 142 mm 轴距。中间航点在路口使用 20 cm 触达半径、其他位置 6 cm，因此停车锚点应从实际下载的连续路径选择，不能假设路径一定穿过输入像素。

`STOP` 不发送任务完成事件，暂停期间仍保持运动状态 2；主机以停止运行标志、实测轮速和关水回读确认停稳。最终出口到达才变为状态 3 并发送 `F0`。状态 3 时仍可读取最终姿态/执行目标快照，但不能再 `RESUME`。

## 暂停路线中的双向视觉对中（2026-11-03）

`0x38/0x39` 仍是障碍信息查询，不得作为移动命令。新增下列接口须先读取 `0x15`：回复 D0=0、D1>=2、D2 bit6=1 才表示支持。旧版 D1=1 的其他功能仍按原协议工作；不得用普通 `0x10 MOVE` 模拟此功能。

| 命令 | 请求 | 回复 |
| --- | --- | --- |
| `0x3C RETAINED_JOG` | D0/D1 有符号 int16 毫米，小端；D2/D3 uint16 mm/s，小端 | `BC [result, host_flags, speed_limit_lo, speed_limit_hi]`；result=0 只表示接收 |
| `0x3D RETAINED_JOG_STATUS` | 全零 | `BD [phase, reason, accepted_seq, flags]`；不可用/参数错误/发送忙为 `FF FF FF FF` |

单步非零距离最多 ±100 mm，速度 20～60 mm/s。正为车头前进，负为倒退。只允许拓展2（`task_mode=2`）保留的导航会话中、主路线已暂停、状态仍为2、有效路线和姿态、IMU正常、泵输出为低、双轮连续100 ms停稳时接受。普通巡航、终点DONE、传感器或路线无效时拒绝。转向指令先回正，之后以本次开始时的地图航向做小角度修正；倒退时修正转向符号取反。距离由双轮编码器积分，当前位置和航向继续使用原惯导坐标，不重设零点。

`phase`：0空闲、1执行中（包含转向回正准备）、2制动等待停稳、3本次有界位移完成、4中止。`reason`：0无异常/正常完成，1 STOP，2通信租约失效或离开导航控制范围，3姿态/IMU/路线代次/执行游标变化，4泵输出非低，5车轮未动，6超时，7编码器异常或运动方向不符，8航向偏离本次直行参考超过15°。`flags`：bit0双轮停稳，bit1当前仍为有效暂停导航，bit2当前允许局部驱动。

每次移动使用新 `SEQ`。同一最近 `SEQ` 和相同参数重复发送只返回既有接收结果，不重启、不追加运动；同 `SEQ` 改参数返回2。只可将与本次命令 `accepted_seq` 匹配的 phase3 且 flags bit0=1 当作完成。`STOP` 即使应答忙也立即中止局部移动，原 `SEQ` 重发不会重新启动。局部完成不发 `F0`，主路线状态仍为2，任务号、路线RAM、代次及游标全部保留。

执行中/等待制动期间拒绝 `RESUME` 和开泵；泵本身也拒绝存在局部运动请求时启动。`3D` 和地图查询均不延长通信租约；执行期间主机仍须发送常规心跳。失联、退出拓展2、IMU失效、路线改变或泵输出非低均中止。串口发送忙不能视为接收成功，主机应读状态核实，不盲目重发位移。

局部运动会使车辆离开暂停位置，但路线游标冻结。X5 必须沿已验证的原路线直线走廊进行小步前进/倒退，并记录原暂停位置；完成逐个火焰处理后先返回该位置（位置误差≤20 mm、航向误差≤8°），确认停稳和关水，再发 `07 RESUME`。不得直接重置地图位置或假设前移后原前瞻点仍在车前。X5 另限制单侧离开暂停点不超过600 mm、累计局部运动不超过1200 mm。
