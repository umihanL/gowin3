# 纯惯导数值精度改进（2026-11-01）

本轮在电脑本地修改 `src/vehicle/vehicle_odometry.v`。仍然采用编码器测距离、IMU测航向并与轮差预测融合；不增加摄像头修正，不恢复运行途中“偏离路线”停车，不修改地图和140/120 mm/s弯速上限。完整工程编译由本轮统一构建记录给出，本文件的RTL测试不等于实车测试。

## 改了哪里

1. **每帧的小数余量不再丢掉。** 编码器距离换算保留9位余量，X/Y投影保留各15位余量，下一帧继续累计。旧代码对每10 ms增量算术右移截断；例如理应接近零的负向投影，也可能每帧变成负1个Q8单位，长时间累积成为毫米到厘米偏差。新实现同时正确处理正向、反向和往返，不把小数误差反复向负方向取整。
2. **转弯按一小段行程的中点航向积分。** 用前、后两个融合航向之间的最短角差计算中点，正确跨越+180°/-180°。旧版把这一段距离都投影在末端航向上，形成系统性的转弯积分误差。中点法适用于短采样间隔；它不是对未知轮胎滑动的补偿。
3. **对外仍给末端方向。** 一个既有CORDIC先算积分方向，再复用它算末端方向。追踪器、车头参考坐标和遥测不会误用中点方向。输出航向从向下截断改为最近0.1°，内部航向仍保留Q16精度。
4. **重新设起点时清理余量。** Reset和rebase清空本轮积分余量。既有IMU融合、IMU重启对齐、编码器异常处理保持原有机制。

没有增加第二个三角运算模块或新的乘法运算；增加余量寄存器、定点加法和复用状态。所测最长一轮49个时钟，按33 MHz约1.49微秒，远短于10 ms采样周期。这个数字是RTL状态机周期统计，不是芯片时序专项验收。

## 上车后怎么进一步提高真实精度

现有参数保持 `WHEEL_DIAMETER_MM=66`、`COUNTS_PER_REV=1560`、`TRACK_MM=168`，没有用猜测数据覆盖已记录的尺寸。提高实车精度的下一步是记录误差并校准，不能仅凭数值仿真宣称精准到点。

1. **先固定地图起点和车头朝向。** 正确声明实际点位和方向；仅1°的朝向偏差，直走2 m就可能形成约35 mm横向误差。初始朝向必须依据实际摆车，不能从目标点反推。
2. **检查直线距离比例。** 在实际地面、正常载荷下前进和后退约2 m，各重复至少3次；记录实测距离、两轮编码器变化及里程计距离。若多次呈一致比例误差，可用“当前有效轮径×实测距离/里程计距离”估计新的有效轮径，再复测。若左右轮计数或偏差不一致，先检查轮径、轮胎和编码器，不用一个公共比例掩盖单侧问题。
3. **检查航向零偏和安装。** 静止记录至少60秒航向，再做左右转弯的重复测试；区分摆车误差、IMU缓慢漂移、传感器异常跳变和轮胎滑动。IMU/电机/电源线安装固定后再测试，不自动把现场未知漂移写成补偿常数。
4. **检查地图与车体参考。** 当前地图点位对应车头参考，运动模型使用后轴；车头距离、实际道路尺寸、舵机中位及转角标定须一致。屏幕上的“到达”仍是惯导估计完成，不是独立外部定位证明。
5. **最后做固定路线重复性。** 选择同一起点、同一朝向、同一路线，记录终点纵横向误差和朝向，重复至少5次。稳定比例偏差适合标定；每次随机变化较大的误差通常需要排查打滑、地面、松动和传感器质量。

纯IMU＋编码器缺少绝对位置观测，误差仍会累积。此次先消除了软件里能明确证明的定点累计和转弯积分偏差；视觉、外部定位或物理标志纠正不在本轮方案中。
