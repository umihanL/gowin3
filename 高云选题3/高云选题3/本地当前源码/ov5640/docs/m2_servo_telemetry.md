# 舵机范围、M2 方向与串口速度

本文记录上版七路串口和 M2 方向修改。当前版本增加设置、触摸驾驶、较快 PI 和新尺寸差速；请使用 [当前设置与驾驶说明](settings_and_drive.md) 及 `ov5640_settings_audit.json`，本页的旧几何和专版审计不用于当前构建。

本次只调整舵机输出范围、M2 驱动/反馈方向及串口遥测连接。摄像头、IMU 驱动/解算、菜单、地图、规划、自动控制、M1 闭环及所有引脚约束保持本次修改前版本。

## 舵机

上电中位仍为 90°。原遥控满舵对应 70°～110°，现在对应 **20°～160°**。摇杆死区、转向正负、按键、舵机 PWM 50 Hz 帧周期及脉宽标定公式不变。

只修改 `src/vehicle/servo_offset.mem` 输出映射：原有控制命令范围 ±30 对应舵机偏移 ±70°；更大命令饱和在同一输出限位。直行命令仍输出 90°。规划、前轮角模型和后轮差速计算沿用原参数，本次没有按新舵机行程重新标定前轮实际角度。

## M2

保持用户接线和 CST 球位：

| 信号 | 球位 |
| --- | --- |
| 编码器 A | F19 |
| 编码器 B | F18 |
| BIN1 / dir2[0] | C17 |
| BIN2 / dir2[1] | B16 |

只在 M2 实例外交换方向位：内部正向 `01` 对应引脚 `10`，内部反向 `10` 对应引脚 `01`，停止 `00` 仍为 `00`。M2 编码器方向参数从 1 改为 0，使换向后的正目标、反馈速度和累计里程符号一致。编码器 A/B 实际接线、滤波、采样、PI 参数、PWM、换向等待和 M1 均不改。

仿真检查真实 PS2 命令下 M1/M2 的正反方向引脚、编码器 AB 状态序列、正反反馈速度和回程计数，并检查 20°、90°、160° 对应的输出脉宽；未代替实车方向测试。

## FireWater

TX 仍为 M15，**115200 / 8N1 / FireWater / 20 Hz**。每帧严格发送七个数值：

| 索引，从 0 开始 | 内容 | 单位 |
| --- | --- | --- |
| 0、1、2 | Roll、Pitch、Yaw | 度，一位小数 |
| **3** | **M1 目标速度** | **mm/s，有符号整数** |
| **4** | **M1 实测速度** | **mm/s，有符号整数** |
| **5** | **M2 目标速度** | **mm/s，有符号整数** |
| **6** | **M2 实测速度** | **mm/s，有符号整数** |

目标速度取现有差速计算后分别传给两路闭环的命令，转弯时两路目标可以不同。实测速度直接取现有编码器速度模块，沿用原来的采样和平均窗口，不修改滤波。

例如 IMU 暂时不可用而电机正在运行：

```text
samples:0.0,0.0,0.0,200,187,75,69\r\n
```

`\r\n` 表示真实 CR/LF 字节。IMU 不可用时三轴角度均为 0，电机目标与反馈继续发送。前三轴的 `0,0,0` 是缺失数据的占位，不能据此判断测量有效；IMU 有效状态仍看屏幕 RUN/错误状态。串口每 50 ms 采一次完整帧，不依赖 IMU 的新样本脉冲；IMU 恢复后自动发送当前角度。串口不再发送 RotXYZ 或四元数；屏幕的 RotXYZ 与 IMU 解算不变。

VOFA 欧拉控件绑定 0/1/2，速度曲线绑定 3/4/5/6。若通道从 1 编号，则欧拉角为第 1/2/3 路，速度为第 4/5/6/7 路。上版十通道四元数查看页面和分析脚本仅用于旧版帧，本次请使用七通道 VOFA。

下载路径始终为 `impl/pnr/ov5640.fs`。构建核对执行 `python tools/verify_navigation_build.py`，再执行 `python tools/verify_m2_servo_build.py`；历史 IMU 专版审计不适用于本次五个文件的改动范围。
