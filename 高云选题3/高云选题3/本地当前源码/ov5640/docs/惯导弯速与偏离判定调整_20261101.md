## 为什么会显示“偏离路线”并停止

原Mode 9控制器每次收到追踪器结果时，会检查当前目标点在车体坐标中的位置。满足下列任一条件，就设置运动状态6、关闭驱动并刹车：

- 目标点横向分量超过正负350 mm。
- 目标点位于车头后方超过40 mm，并且目标点距离大于40 mm。
- 末段越过终点到达平面，但横向位置超出原先的车宽走廊，也被归为状态6。

这里的“位置”来自轮编码器距离与IMU航向积分，并非摄像头发现车辆压线。路线上有很多采样点；转弯时跨过一个采样点、未进入它原先的60 mm取点窗口，目标就可能落到车后。轮径/每圈计数标定、轮胎滑动、IMU偏航误差、车体参考点与地图摆放偏差，也会改变估计位置和相对目标分量。这些是代码支持的触发机制，**本轮没有拿到用户当次停车瞬间的传感器日志，不能据此断言实车到底是哪一种原因**。

新回归在上一版真实RTL上复现了：目标仍在前方200 mm、横向400 mm时，出现 `status=6 speed=0`。同样刺激在新版不会触发几何偏离停车。

## 修改后的行为

1. Mode 9运行期间取消上述横向偏移、车后目标的“偏离路线”故障。误差仍输入真实追踪器并用于转向纠正；没有把误差或坐标伪造为零。
2. 中间点除原有60 mm窗口外，增加按**当前路线段的到达平面**推进：估计位置越过该段目标平面后，切换下一点，避免继续追赶已经错过的采样点。判断使用地图段向量与剩余位移的点积，与车头此刻朝向无关；既有18 mm平面容差沿用。
3. 终点仍按原有18 mm距离或末段到达平面停车，结果记作正常的惯导路线完成3，不再因横向走廊给出状态6。它表示估计位姿已完成路线，不代表相机或外部设备已核实车体到达实物终点。
4. 保留起步朝向与路径首段不符超过35°的启动拒绝，状态仍为6；FPGA屏幕标签由“偏离路线”改成**“朝向不符”**，避免与已取消的运行时判定混淆。
5. IMU超时、编码器异常/反向异常、车轮堵转、路线失效、操作员暂停/退出及正常到达停车保留。独立减速停车/绕障任务的功能不变。

纯惯导的定位误差不会因取消故障判定而消失。尤其末段横向误差较大时，“路线完成”不能作为已对准楼栋、水枪或精准停车的实测证据；X5既有 `physical_position_verified=false` 的含义仍适用。

## 弯道速度

| 追踪器转角绝对值 | 上一版上限 | 新版上限 |
|---|---:|---:|
| 不超过12° | 200 mm/s | 200 mm/s |
| 大于12°、不超过24° | 160 mm/s | 140 mm/s |
| 大于24° | 140 mm/s | 120 mm/s |

这些是速度上限。较低的用户速度设置、起步加速和终点减速仍有效，出弯后按原有速度斜坡恢复直线速度。没有修改地图道路、转弯几何、舵机限位或IMU参数。
