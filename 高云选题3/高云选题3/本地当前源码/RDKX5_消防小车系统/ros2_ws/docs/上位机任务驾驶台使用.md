# 上位机任务驾驶台使用

**2026-11-04 语音总开关（已部署 X5）**：任务驾驶台 → 车载语音增加“开启语音 / 关闭语音”。未接麦克风和音响时可关闭，暂停收音、语音识别、语音播报并释放已加载的音频模型资源；文字导航、文字问答、YOLO 和车辆任务继续可用。开关保存在 X5 的 `config/voice_runtime.local.json`，重启后保留；首次运行新版且没有该文件时默认关闭。后续插好 X5 上的麦克风接收器和音响，再点“开启语音”，等车端确认后点击开始收音；开启开关不会重放旧录音或旧回答。设备型号、模型、音量及各音频功能的原有启用配置仍使用 `voice.local.json`，不会被开关覆盖。本次已部署到 X5，并通过同一上位机接口收到“关闭语音”生效回执；当前收音、识别与播报均关闭，文字指令入口保持就绪。

**2026-11-01水枪接线更新（本地待部署）**：水枪由FPGA B13驱动MOS控制输入。电脑按钮和语音入口沿用，X5经现有UART下达有限时脉冲，上位机显示FPGA输出开启、关闭或未知。旧X5物理16脚方案停用；详见《拓展任务与水枪接线_20261031.md》。惯导新增定点余数与中点航向积分，仍只用地图、IMU和编码器；数值改善不等于实车定位已验收。

**连续收音修复（本地待部署）**：每次点击“开始收音”建立独立轮次，说完后点击“说完提交”。正常完成后可继续下一轮；若提示识别超时，本次不会执行，重新开始时会重建识别进程，避免上一轮原生计算一直占用。恢复时可能重新加载模型，请等“正在车载收音”再说话。此处控制X5上的无线麦克风USB接收器，不使用电脑麦克风。

> 2026-11-01最新本地更新：编号导航的文字与语音统一走规则解析，Qwen保留场景分析与问答。首次必须提供实际起点和地图朝向。双目固定车身、云台只带喷嘴；任务按钮只切模式。先读《当前任务流程与固定双目瞄准.md》。本轮只在本地准备，须配套更新X5程序与FPGA位流后才会生效，不覆盖此前部署记录。

界面只保留三个主入口：**任务驾驶台、视觉与瞄准、设备调试**。运行的是 X5 本地模型和实际任务节点，电脑负责显示、收音请求和文字指令。无线麦克风的 USB 接收器仍插在 X5；电脑不采集麦克风音频。

顶栏的“停车 · 停水”和“停止喷水”在所有页面常驻。提交成功只表示请求已接收，完成状态必须看车载回执。

## 电机位置丢失时恢复

在 **设备调试 → 云台绝对角度控制** 点击 **“重置连接 / 恢复控制”**。即使上次运动中止、两轴角度暂时显示横线，也可发起重连；页面保留输入草稿。车端取消旧动作、确认关水，重新读取两个串口，并用已保存的绝对编码器参考恢复机械角度。回执显示“连接与固定零位已恢复”后，重新点击“运动到角度”。恢复操作不改变零位，不重放上次目标，也不自动喷水。

异常状态显示具体的运动中止原因，能够取得的新鲜诊断角度继续显示。驱动器仍无回包、仍在转动或确实越过机械范围时，会显示具体原因，允许再次点击恢复；不能把未测得的位置显示成零度。

## 1. 任务驾驶台：日常演示从这里开始

界面从左到右是对话、真实相机画面、FPGA 地图。顶部只保留三种任务入口：待机、拓展一、拓展二。

### 观察和问答

1. 点“拓展一”。X5 开启火焰、人物、消防员识别以及语音、文字问答；这条功能链不要求 FPGA 接通。
2. 点“开始收音”，等状态显示正在收音后讲话。默认采集 15 秒，可点“说完提交”提前结束，不需要一直按住按钮。
3. 例如说“画面里有几团火焰”“有没有消防员”“分析当前火场”。也可以输入同样的文字。
4. 右侧显示你的问题，左侧紧接小车的回答或任务回执。Qwen 使用视觉节点的证据回答；不会从聊天回答直接产生底盘运动或喷水。

“提问与指令”打开完整示例；“分析火场”快捷项只是填入输入框，点发送后才提交。收音和文字框在交通任务期间暂停，防止任务互抢。

### 语音编号导航

1. 选择“拓展二”，确认 FPGA 固件、独立 UART、通信模式以及车辆停稳反馈正常。
2. 首次可直接说或输入完整声明：**“你现在在8号点位，车头朝地图左侧，请导航前往至4号点位。”** 规则提取8→4和180°，程序核验后提交。也可展开“起点确认与辅助选点”，选择实际点8、输入180°，勾选实际位置与朝向后确认。右0°、上90°、左±180°、下−90°；数字框支持斜向角度。
3. 已有可靠起点与朝向后可说“去 4 号点”或“从 8 号点到 4 号点”。**不需要先点目标按钮。** 文字与语音转写使用同一规则，不调用Qwen；仅声明当前位置而没有目的地不会发车。真人语音另经独立转写核对数字与方向。不支持或含糊的句子会要求补充，不让模型猜测。
4. 原指令下方显示规则提取的起点、方向、终点或澄清原因。提交后的进度是：设置起点 → 设置真实朝向 → 选点 → FPGA规划 → 启动 → 行驶 → 到达事件与停稳确认。导航无需等待场景Qwen回答完成；停止、切模式或参考变化仍会取消冲突或失效请求。
5. 到点并确认停稳后进入固定相机YOLO观察，等待你选择火焰；不自动扫描喷嘴或喷水。后续单独下达瞄准、喷水命令。

点击地图点号只会把“去 N 号点”放入输入框，**不会立即移动车辆**。辅助数字按钮和“开始导航”仍保留在展开面板里，适合没有语音时操作。起点确认与目标选择是不同操作。

聊天框发送地图填入的文字也走规则解析；辅助面板的结构化“开始导航”直接进入相同导航状态机。普通到达后可用新鲜IMU终点朝向继续下一程；车辆被抬起搬动、重新上电或参考失效后必须重新确认。不得根据目的地反推车头朝向。

最新版导航采用IMU＋编码器，运行中不因普通障碍、斑马线或几何偏离判定而停车；中间点已跨过时继续下一段。弯道两档上限为140/120 mm/s，直线200 mm/s。人工停车、链路或传感器故障及终点停车保留。“到达”是惯导估计完成，不能当作实物定位精度已验证。

### 地图读法

- 灰色道路：与 FPGA 地图 ROM 同源的底图，不是旧 Blender 场景。
- 点号：1～9 号导航点，不自动等于楼栋号。
- 青色线：FPGA 实际回传的规划路线。
- 绿色箭头：FPGA 编码器和 IMU 计算的**车头中点**，箭头尖端锚定回传位置。它是里程计估计，不是外部绝对定位。
- “底图就绪 · 位姿未知”：只有静态图可用；旧固件、串口未接或回包过期时不画预测小车或虚假路线。

当前已确认的起点以点号边框提示。它是操作员确认或到达证据，不能替代连续位姿遥测。

## 2. 视觉与瞄准：目标操作和交通验证

### 火焰瞄准

当前轴分工：**水平 = 电机2 ZDT_XS（PIN3 TX / PIN5 RX）；俯仰 = 电机1 PD42（PIN8 TX / PIN10 RX）**。接线和电机编号不换，只交换轴功能。自动瞄准、自检和实测角度读数均按这个分工；轴的正方向、限位和参考角仍须实测确认。

1. 在“火焰瞄准”标签查看识别结果和火焰编号；必要时点“开启火场识别”。
2. 选择目标或说“瞄准第 2 个火焰”。实际电机角度显示在水平轴、俯仰轴读数中；目标角度和实测角度分别显示。
3. 图像锁定、车辆停稳、距离/落点补偿和真实水泵条件均由板端核对。显示“图像已锁定”不等于水流已经命中。
4. 需要喷水时单独下达“开始喷水”或点“确认短时喷水”；危险动作仍有明确确认。用“停止喷水”结束。

“双轴小幅自检”展开后可选择水平轴、俯仰轴或双轴。程序只在板端明确 `can_start=true` 时允许请求 ±1° 往返自检，不自动归零；没有新鲜实测角度或停车证据时按钮禁用。界面的自检完成必须来自真实反馈，本地代码测试不能显示为实机验收。

### 红绿灯与楼牌

1. 切到“红绿灯与楼牌”标签，点“开启识别”才启动交通任务。切标签本身不会切任务。
2. 仅观察红绿灯时无需点“开始行驶”。真实交通行驶必须单独启动，并满足 FPGA 斑马线开关、通信、停稳等条件。
3. FPGA 识别斑马线并停车，X5 按任务流程识别灯色；稳定绿灯才发放行请求。未知或红灯保持停车。
4. 同页可看 OCR 文字、楼栋名称和场景关联证据。看到楼牌和看到人物是两项证据，不会自动当成整栋楼的人数。

结束交通任务后再回到驾驶台开启拓展一或拓展二。

## 本轮验证边界

本轮三页面及子面板在 1280×720、1366×768、1920×1080 做本地浏览器验收。验收截图明确标记“本地界面验收（未连接硬件）”，位于 `reports/hmi_task_console_20261031/`。测试 HTTP 夹具不连接 X5、FPGA、电机或水泵，不是产品的模拟任务模式。

EXE 是 WebView2 桌面壳，真实连接时读取 X5 的 8090 服务。2026-10-31 已重新构建并检查 EXE，桌面快捷方式为“消防救援控制台（最新版）”。本轮还新增了地图遥测和双轴后端，需部署完整更新包，不能只复制三个 Web 文件；更新板端后重新连接即可加载。复制或打开新版 EXE 不会自动更新 X5。

地图实时位姿、路线和禁行线需要配套新版 FPGA 固件。当前源码已在 2026-10-31 完成 Gowin 综合、布局布线和现有约束下的时序核验，新位流位于相邻 `ov5640/impl/pnr/ov5640.fs`。随后已在用户授权下完成 Flash 烧录、校验和重新加载，记录为 `ov5640/diagnostics/programming_20261031_185855/result.json`。**X5 本轮更新仍未部署**；缺少板端程序、UART 回包或新鲜位姿时，上位机仍只显示底图，不会补画虚假车辆。今天之后的纯本地验收没有再次连接 FPGA。

按照本次要求，未连接 X5，未旋转真实电机、启用水泵或部署到板端。本地界面通过不代表真实底盘、双轴、水泵验收通过；正式瞄准仍需验证方向、减速比、原点、限位、停车证据，以及水流落点补偿。

## 桌面启动与无互联网热点

### 2026-11-04 区域搜索对中修订

区域语义导航现改为搜索消防员。小车沿原路线持续检测消防员，稳定识别后停车，缓慢前进或后退，将当前批次的消防员逐个调整到画面中线附近，停稳观察后返回原暂停位置并继续原路线。该任务不请求云台瞄准、自动灭火或喷水；独立火焰识别、瞄准与手动水泵功能保留原入口。

手动试喷现在先发送本次明确关水，等待匹配的新鲜低电平与就绪状态后再短喷。FPGA 必须处于“拓展2对话控制”页；首页下显示的“未进入控制页”表示开启命令未发出。按“停止”后不再需要先手动解开水泵锁，下一次新的试喷请求会执行关水准备。直线水流策略不要求实测落点表，但自动瞄准仍需要可用的双目控制距离、安装几何及两轴实际角度。

如果云台只缺少串口回读、喷嘴已在现场固定静止，可在试喷窗口勾选本次固定喷嘴确认，再进行一次 100～1000 毫秒的 B13 试水。确认框每次提交后清空，不会恢复电机、自动瞄准或重放旧动作。后台仍核对真实停车、FPGA 控制页、通信、关水及控制任务空闲；已知运动、驱动故障或未结束的旧运动不能通过勾选解除。界面显示的 HIGH→LOW 是 FPGA 输出反馈，实际出水仍需现场观察。

消防员搜索中，识别到稳定目标后暂停原导航路线，逐个调整目标到画面中线附近。中心容差为画宽的 ±5%（1280 像素画面约 ±64 像素），仍需三次独立图像确认、实测停车后保持一秒。这个容差用于小车停车观察。

微调与主导航共用 FPGA 的惯导健康状态和里程计。单次运动结束后等待两次独立且稳定的停车位置；回原观察点统一按 20 mm 范围确认。短步未到指定终点时，程序重新读取图像与实测位置后再决定下一步。当前消防员连续三次同方向短步仍无法完成时，若车辆确实停稳、仍在可行走廊内且每步都有正向进展，则将该目标记为“观察未完成”，再处理其他目标。返回原观察点的运动仍须实测到位，才能继续原路线。

当前直线路段无法继续对中某位消防员时，上位机保留它的未完成原因。真正越出已检查走廊、反向或没有进展、定位失效、路线被更换、通信丢失时仍停车；提示包含具体原因，日志保存第一次失败的实际位移和目标位置。

没有接麦克风和音响时保持“语音关闭”。这不会关闭文字指令、YOLO 或区域搜索。重新接入设备后再打开语音开关。

双击桌面“消防救援控制台（最新版）”。实际程序是系统目录 `desktop/dist/消防救援演示台.exe`，请保留旁边的 DLL，桌面放快捷方式即可。

电脑和 X5 连同一个手机热点，在顶部填写 **X5 当前无线 IP:8090** 后点连接。手机可以关闭移动数据；热点必须保持开启并允许两台设备互访。`192.168.127.10` 是网线地址，无线连接应读取板子的实际地址。X5 已有 Wi-Fi，不需要专门再买 USB 无线网卡。

## 2026-11-01：USB 音响与自然中文播报

音响插在 X5 上，电脑上位机仍控制车载麦克风收音。文字回复经 `/speech/say` 进入语音节点，再由本地 Matcha 中文声学模型和 Vocos 声码器合成并送到 USB 音响；不需要互联网。ASR 识别、导航规则和 Qwen 场景理解继续使用原配置。

活动语音配置为 `/root/rescue/ros2_ws/config/voice.local.json`。自然语音使用 `tts_backend=sherpa_matcha`、`tts_enabled=true`、`tts_prewarm=true`、`tts_threads=2`；模型目录为 `models/voice/tts/matcha-icefall-zh-baker`，声码器为同级 `vocos-22khz-univ.onnx`。模型启动后在独立进程中预热并缓存，停止服务会回收；推理超时可以重试，不在 ROS 回调中执行耗时合成。

本次音响是 Jieli USB Composite Device。输出使用实际配置的 `tts_audio_device`，不能把麦克风序号填成音响设备。合成音量采用 `tts_normalize_peak=0.85`、`tts_max_gain=4.0`，弱音有界增强，近静音不放大。硬件 PCM 音量现场调为 80%；换音响后须重新检查 `aplay -l` 和设备音量。

上位机开启拓展任务后，可输入“分析当前火场”或询问画面信息，查看文字回复并听取播报。相机事实仍受识别结果和数据时效限制。等待模型预热完成后再验收语音，刚启动的第一次请求可能更慢。

独立试听工具不会录音、导航、旋转云台或喷水：

```bash
cd /root/rescue/ros2_ws
.venv/bin/python tools/check_neural_tts.py --config config/voice.local.json \
  --text '你好，我是消防救援小车。' --output /tmp/rescue-speech.wav --play
```

现场候选模型测试（任务控制服务停止、相机服务运行）中，同一句中文由旧 VITS 的约 24.9 秒降到 Matcha 的约 7.0 秒；短句“现在开始分析火场。”约 1.84 秒。首次模型加载约 13 秒，可由后台预热提前完成。以上不是视觉、OCR、Qwen 同时满载时的保证值，正式服务实测以 `reports/pump_audio_deployment_20261101/` 的记录为准。

模型来自 sherpa-onnx 官方发布渠道：`k2-fsa/sherpa-onnx` 的 `tts-models/matcha-icefall-zh-baker.tar.bz2` 和 `vocoder-models/vocos-22khz-univ.onnx`。本机同时保留候选 VITS 模型用于比较；是否启用以活动配置为准。

## 导航回执与音响故障定位（2026-11-01 修订）

拓展 2 的区域搜索入口为：“在A区域搜寻消防员”或“去C区域搜索消防员”。先在地图上确认实际起点和车头方向，再下达 A/B/C/D 区域任务；程序沿搜索路线持续识别消防员，稳定识别后停车，缓慢前后对中并停稳观察，处理当前批次后返回原暂停位置并继续。消防员目标不进入火焰选择、云台瞄准或喷水链路。旧的区域火焰搜索及区域搜索灭火口令会提示改用消防员指令。完整操作与起点箭头说明见 [《语义区域搜索与地图导航》](语义区域搜索与地图导航.md)。

文字和麦克风转写共用规则导航入口，例如“我现在在8号点，车头朝左，请前往4号点后停下”。必须按实际摆车填写点位与朝向。解析成功仅代表理解了指令；聊天框随后显示同一 command_id 的执行节点回执。节点接收仍不等于车辆已运动，是否开始、是否到达以 FPGA 导航状态和实车为准。执行节点拒绝会在原问题下显示具体原因；等待超时不会自动重发移动指令。

导航要求新鲜的 FPGA B13 输出关闭反馈及水泵未武装。云台尚未标定或执行器处于 dry-run 时，仍读取来自真实 UART 的 B13 状态，不再把它误丢弃为未知；这不会启用云台或水泵。没有回包、过期、错误或输出为高时，仍拒绝移动。B13 回读只证明数字输出电平，不证明水流状态。

播报依次显示“合成语音”和“正在播放”；输出设备丢失时显示 USB 音箱问题，错误不会被普通心跳覆盖。重新插接音箱后，下一条新播报会重新检查设备。丢失或过期的旧回复不会自动重播，请重新提问。文字回答存在不代表已播放；播放程序成功也不代表现场音量足够，需要实际听取一次。当前补丁的部署与现场验收结果见系统目录 `reports/navigation_speech_20261101/`。
