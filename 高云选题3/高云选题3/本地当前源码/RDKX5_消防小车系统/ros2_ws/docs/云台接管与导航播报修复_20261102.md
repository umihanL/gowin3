# 云台接管、地图起点导航与回答播报

本次修改 X5 的任务程序和上位机。沿用已烧录的语义区域 FPGA 固件，无需因此重编 FPGA。板端是否已更新，以 `reports/control_audio_fix_20261102/` 的最终部署记录为准。

## 1. 任意起点去编号目标

原先“地图设置起点”和“编号点起点”分开保存，地图确认后说“去4号点”仍可能报“请确认编号起点”。现在已统一使用当前有效参考：

1. 在 FPGA 选择通信导航/拓展2页面，上位机开启拓展2。
2. 在地图标记实际位置，重复点击起点调整车头方向，然后确认。
3. 输入或说“去4号点”。程序以该坐标与朝向进行 FPGA A* 规划，无需把起点强行改成1～9号点。

普通点位导航不要求云台、双目测距或水泵具备作业能力，但仍须有新鲜的关水、未布防及实测停车反馈。到达仍须核对本次任务的完成回包、实际停车和新位置；不会因收到 ACK 就宣布到达。下一程使用本次真实回传位置。重启或搬动车辆后须重新确认起点，程序不从旧日志恢复猜测的位置。

## 2. 正式云台接管

安装信息由用户确认：电机2 ZDT（PIN3/5）水平直驱，零位左右各90°；电机1 PD42（PIN8/10）俯仰直驱，从水平向上0～60°。喷嘴已安装，有俯仰支撑，每次上电人工摆到约定零位。

“电机已经使能”表示驱动器有保持力；正式 ROS 控制还需要本次编码器参考。`tools/capture_mixed_reference.py` 只读取两轴状态、记录人工零位，不使能、不移动、不清零、不修改电机菜单。它要求三轮静止反馈、实际位置与驱动保留目标一致；失败时不生成活动配置。

在两轴已摆到约定零位、静止、正式执行器与电机调试页均释放串口时执行：

```bash
cd /root/rescue/ros2_ws
.venv/bin/python tools/capture_mixed_reference.py \
  --operator-zero-confirmed --supported-load --apply
```

生成：

- `config/actuator_io.mixed.local.json`：本次实际编码器参考、实测驱动参数快照和行程。
- `config/local_fire_control.local.json`：正式云台控制启用，水泵仍禁用。
- `/run/rescue/gimbal-profile.json`：与本次启动ID、配置哈希和参考ID绑定的启动资料。

原有活动配置会备份。重启任务服务后，`run_standalone_tasks.sh` 自动采用这份通过校验的启动资料；缺失、配置变化或 X5 重新开机时回到调试状态，避免把旧计数当作新零位。电机若单独断电或被手动挪动，必须重新检查，不仅看 X5 是否重启。

首次启动还会核对驱动器保留目标与捕获时的目标。若在偏转位置重启任务服务，旧参考可能被拒绝；应在重启前回到本次零位，或重新摆到约定机械零位后捕获。不要把任意偏转姿态直接重新登记成机械零位。

省略方向参数时，该捕获入口仍将俯仰锁在水平参考，只开放水平到角度；两轴都会回读。不能把电机正计数方向猜成喷嘴向上方向。

本次已进行 PD42 正向约 1.8° 小幅测试、保持 6 秒并回到参考零位，现场确认第一次运动为喷嘴向上。安装和接线未改变且已回到约定零位时，可明确记录这个观察结果并开放俯仰：

```bash
.venv/bin/python tools/capture_mixed_reference.py \
  --operator-zero-confirmed --supported-load \
  --tilt-positive-direction up --apply
```

`up` 表示电机正向运动使喷嘴上抬，对应俯仰 `direction=+1`；若另一种安装经现场确认正向使喷嘴下压，使用 `down`，对应 `direction=-1`。两种情况均保持俯仰目标范围 0～60°。只有显式提供该参数才开放俯仰，不提供时仍锁定；不要为了使按钮可用而猜测方向。配置中的 `commissioning.tilt_direction_confirmation` 记录操作者观察确认来源，命令输出 `motion_axes` 显示本次实际开放轴。此命令本身只读取电机，不发送测试运动，也不完成相机到喷嘴的三维外参或水流落点标定。

## 3. ZDT 的180°行程

正式水平控制使用已匹配配置的 ZDT Emm FD 位置指令，一次下发完整剩余目标脉冲，取消固定8脉冲、每0.9°停稳后再发下一段的限制。命令仍相对驱动保留目标换算，界面目标仍相对已保存机械零点；重复输入30°不会累加成60°。90°对应800脉冲，从−90°到+90°对应1600脉冲。

保留原速度编码1、加速度编码1、每秒最高20次闭环回读和机械±90°范围。指令分辨率为1.8°/16=0.1125°，这是位置量化单位，不是每次只准走这么多。长行程期间允许实时轨迹目标在起终点之间变化；最终保留目标、实际角度和静止回读仍需一致。通信失联、目标异常、超限、4秒无实际进展或总行程超时会停止，超时不重发位置包。

当前 FD8 驱动的静止回读出现过连续 20 次以上的残差：实际位置 −3 计数、保留目标 16 计数，相差 19 计数（约 0.1044°）。因此仅该 FD8 配置的实际位置/跟随误差收敛门槛统一为 0.15°，零位捕获与运行控制共用 `zdt_vendor_bench.STATIONARY_TOLERANCE_DEG`。仍要求零转速、两个目标寄存器一致、三轮稳定读数，采样漂移不超过 0.03°；PD42 俯仰的独立门槛不变。这是允许驱动器稳定残差，不是测量精度或水流命中精度的声明。

上位机“设备调试”中的“云台到角度”用于正式控制。角度可以提前输入；本次零位、真实反馈、范围和对应轴权限齐备后，点击“运动到角度”才会执行。未开放俯仰时应留空俯仰目标；输入了未开放轴的目标会拒绝整次提交，不会静默忽略。“停止”取消当前动作。原“电机1/电机2”空载调试页仍是独立工具，不能和正式控制同时占用串口。

同一位置新增 **“回待机位（0° / 30°）”** 按钮：点击后把水平目标填为 0°、俯仰目标填为 30°，通过原有 `/api/gimbal-manual` 发起一次真实到位运动。无需新增开关接线；这是代码执行的固定角度动作，沿用本次已确认的编码器参考，既不清零，也不重新捕获参考。原有任意角度输入与“停止云台”继续保留。只有两轴均开放运动、正式输出启用、反馈新鲜且两个目标均在真实行程范围内时，按钮才可用；鼠标悬停可查看未就绪原因。请求失败、断线重连或状态刷新都不会自动重发。

**软件回待机位与硬件找零不同。** 待机姿态为水平 0° / 俯仰 30°，约定的机械参考姿态仍为水平 0° / 俯仰 0°。这个按钮不会寻找限位开关或识别机械原点；已有绝对编码器固定零点时，重新上电按后述只读恢复流程接管；旧版本没有绝对零点记录时需先记录一次。不能在俯仰 30° 的待机姿态把它重新登记成机械 0°。运动完成以电机回读和到位回执为准，按钮下发不代表已经到位。

正常到位完成后，两轴保持在目标位置，不再因动作完成而自动释放保持力矩；仍以编码器反馈核对实际位置。显式“停止云台”、故障或超时仍按停止策略释放驱动，俯仰负载必须有支撑。保持位置不会继续追逐目标、重发新的运动任务，也不会开启水泵。

完整区域“搜索并灭火”还要求已验收的双目、相机/车身/喷嘴标定及水泵就绪。启用角度控制不代表已经证明自动瞄准或水流命中。

### 当前正式启动方式：真实串口常在线

### 固定零点与绝对目标角度

现在的目标是固定坐标角度：发送水平 30°，表示到固定零点右侧 30°；再次发送 30°不累计成60°。PD42 俯仰使用驱动器绝对位置指令；ZDT 水平根据已保存参考和驱动器保留目标换算剩余脉冲，一次下发完整目标行程，并以实际编码器回读确认到位。

一次记录机械零点时，同时保存 ZDT 的单圈绝对编码器 0x31 与 PD42 单圈位置，并绑定安装方向、减速比和限位。以后开机先读取两轴单圈绝对位置，重建当前驱动器坐标中的零点；这个过程只读，不转动、不清零、不自动回到0°，也不把每次开机的位置重新定义为0°。永久记录保存在 `config/gimbal-absolute-profile.local.json` 及其引用的本机配置中，完整写入并核对后才开放角度动作。

当前两轴直接驱动、行程分别180°和60°，可在单圈内唯一恢复。更换驱动器、电机重新校准、外部执行PD42 F8清零、改变减速比或安装方向后，需要重新记录固定原点。恢复时读数或配置不一致会显示具体原因，不用假定当前就在零位。旧版本只有开机计数的配置需记录一次绝对零点后，才能启用跨开机恢复。

正式离线启动不再因缺失本次零位记录而退回 `dry_run`。每次启动都使用真实双串口；尚未确认机械零位时，上位机显示两轴原始编码器计数、转速和通信状态，机械角度显示“—”。零位未确认与电机未连接分别显示。串口暂时失联时只重试读取，不自动续发运动指令。

进入“设备调试 → 云台到角度”，将喷嘴摆到**水平居中、俯仰水平（0°/0°）**，保持静止并支撑俯仰负载，勾选实际姿态确认，再点击“确认当前位置为机械零位”。程序核对三轮串口读数与驱动器保留目标，保存参考并直接开放角度控制，无需终端或重启服务。已经标定后按钮显示“重新记录当前位置为机械零位”，可重复操作；每次都需重新勾选实际姿态确认。确认本身不使能、不转动、不清驱动器编码器；它只建立软件机械角度参考。单纯打开页面、断线重连和开机都不会替用户确认实际姿态。

手动重新摆放造成的“实测位置超出原参考/行程”故障，可以在重新摆正、原始编码器读回稳定后，通过此入口重新建立参考。通信故障、急停、驱动器保护和运动中的状态不作为可重标条件。重新标零会生成新的参考编号；相机到喷嘴及水流落点的数据仍需与当前参考一致，不能把重新标零当成水流命中标定。

水平 ZDT 运动期间的闭环采样上限为20 Hz，完成后恢复空闲频率。新版提速来自一次执行完整剩余角度，保持最终到位确认；此前0.9°分段仿真的耗时不再代表新版。多脉冲长行程仍需实机验收。

原有方向、减速比和机械限位沿用已确认安装资料：本车水平 ZDT 为 −90°～+90°，俯仰 PD42 为 0°～60°，俯仰正向上抬。如果驱动器保留目标与实际位置不一致、读数在运动、配置不匹配或存在故障，会给出具体原因，不把不一致读数登记成有效参考。配置缺失时可回读串口，但不能猜测安装方向或限位。

水泵未启用且没有活动喷水请求时，缺少 FPGA 水泵回报不再阻止独立云台调整；实际报告正在喷水、待执行喷水请求或活动喷射仍会互斥。相机几何与水流落点标定仍独立于本次电机参考。

### 按钮不可用时看哪一项

正式“云台到指定角度”页也可能不可用，并非只有空载页会禁用按钮。页面现在分别显示“服务连接、控制节点、控制状态、双轴回读、本次零位”。能加载网页只证明 HTTP 服务可达，不证明 ROS 云台节点已启动；例如串口打开或独占锁失败会使执行器节点在发布状态前退出。仅凭“没有新鲜云台控制状态”的旧截图不能判断具体是哪一种原因。

角度输入框在离线、状态缺失和请求等待期间都可编辑。已提交的角度不会随着输入框修改而改变；修改只作为下一次点击提交的草稿。运动与回待机位仍需当前控制节点、角度反馈和本次参考就绪，重连不会重发旧指令。

“双电机”是独立的**空载调试页**，不代表正式云台的连接状态。正式云台启用后不能让该页再次占用同两路串口。上位机现在会在页顶、两张卡片正文和状态标签显示实际禁用原因，并提供“打开云台到角度”按钮；该按钮只切换页面，不发运动、使能或连接命令。第一次进入“设备调试”且收到新鲜的正式执行器启用状态时，会默认打开“云台到角度”；主动选择过其他子页后，轮询不会把用户强行切走。

| 显示情况 | 含义和处理入口 |
| --- | --- |
| 整车连接失效 | X5 未上电、网络不通或车载服务连接中断。此时不能判定电机串口断线；先恢复 X5 实时连接。旧的占用或故障信息不会继续冒充当前状态。 |
| 网页服务已连接，ROS 未就绪 | 网页进程还在运行，但车载 ROS 通信没有正常工作；需检查交互服务启动日志。 |
| 未发现控制节点 | 网页的 ROS 接口没有发现正式云台请求订阅者；检查云台节点启动日志及串口占用，不能仅靠切换网页解决。 |
| 控制状态／执行器状态尚未收到或已过期 | 分别表示未收到发布状态或之前收到的状态已失效，不等于电机已断线，也不自动判为零位未记录。等待实时状态或排查车载发布节点。 |
| 正式云台正在管理两路电机串口 | 空载调试被正常互斥，不能再次“连接并读取”。进入“云台到角度”看正式角度、就绪原因与运动回执。 |
| 本次开机零位尚未记录／等待双轴真实反馈 | 本次参考或反馈条件尚不齐备。角度输入仍可编辑并保留；完成前述上电参考确认和回读后再提交，不自动续发旧请求。 |
| 正式云台故障 | 显示车载 `actuators.error` 原文，包括越限时的 `actual_deg`、编码器计数和 `limits_deg`。这是实测姿态与参考/行程的冲突，需要核对实际安装位置；页面不会为了让按钮变亮而清故障、改零点、重启或夺取串口。 |

空载页的“停止空载测试并失能”仅结束该页的测试；正式动作使用“云台到角度”的“停止云台”。正式串口常在线后，空载页仍不会抢占同两路串口。部署与本次实机回读结果见系统 `reports/gimbal_live_start_20261102/`；软件回归或只读回包不代表已经验证实际到位及水流命中。

## 4. Qwen回答由USB音响播报

拓展1中说或输入“分析当前火场”，回答会经现有 `/speech/say` 通道发送给板载中文语音模型，再输出到 `plughw:CARD=RescueSpeaker,DEV=0`。USB音响必须插在 X5。

修复了之前超过350字的回答被丢弃的问题：现在接受最长900字完整回答，按句分成每段不超过180字连续合成播放；保留结尾的事实限制说明。途中拔下音响会结束当前播报，重新插入后可播报新回答，不自动播放过期答案。停止时显示中断，不冒称播放完成。

Qwen输出若与当前检测事实不一致，仍会使用结构化事实回答并显示回退原因；两种回答均可播报，不会为了能播放就删除事实校验。
