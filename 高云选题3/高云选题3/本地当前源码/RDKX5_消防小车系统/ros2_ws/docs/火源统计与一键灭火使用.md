# 火源统计与一键灭火

更新日期：2026-11-04。部署与实机只读状态不等于已完成道路运行或喷水命中验收。

## 原先为什么点不了

1. 火焰编号按钮曾经依赖云台输出就绪；现在只需进入火场识别、车辆停稳且目标新鲜稳定，就能选择目标。电机尚未使能或标定未完成时，也能先选目标。
2. “设备调试 → 云台到角度”的标签存在，但页面切换白名单漏掉该页面，点击后返回双电机页；已修复。
3. 拓展任务原先拒绝通用 `auto_fire` 请求。现在增加明确的 `extinguish_selected`，只处理你当前选择的一团火焰，不改变旧的通用自动任务行为。
4. 实际设备状态还曾报告 dry-run、无当前开机零位、无实测双目/喷嘴/落点标定。界面问题修好不会自动补出这些实测数据。

## 手动选定一个火焰并完成一轮

### 未完成标定时先测水路和落点

在“视觉与瞄准”顶部点击“手动试喷”。选择 0.1、0.2、0.4、0.8 或 1 秒，确认当前喷嘴朝向后点击“执行一次短喷”。这会通过 FPGA B13 按**当前喷嘴方向**输出一次真实脉冲；不用先选火焰，也不要求双目或水流落点标定。它不会自动转动喷嘴。

默认选择 0.4 秒。一次点击最多 1 秒，不循环、不续喷、不自动重试；“立即关水”和全局“停止喷水”均可终止。试喷与车辆/云台运动互斥，结束后必须收到新的关水反馈才放行运动。B13 高低电平只能确认控制输出，实际出水仍看现场。

文字或语音可输入 `手动试喷四百毫秒`（也支持 `手动试喷400毫秒`）；只说 `手动试喷` 时使用 400 毫秒。停止口令为 `停止试喷` 或 `停止喷水`。文字请求会确认当前喷嘴方向，语音请求会独立复核动作和喷时；不经 Qwen 推理。问句、否定句或“试喷然后前进”等复合指令不会执行试喷。

正式离线启动脚本已设置 `manual_pump_test_enabled:=true`，只开放人工试喷入口，开机仍不喷水。该权限独立于云台 dry-run 和自动灭火权限，未标定不会因此使自动瞄准变成已标定。直接启动底层 launch 时该参数默认 false，需要显式传入 true。

若按钮仍不可用，界面会提示具体原因，例如 FPGA 未连通、尚未确认停稳、水泵反馈过期、正在运动或上一轮关水未确认。这些反馈条件保留。没有硬件连接的电脑预览不会发送真实输出。

`FD8 overspeed or excessive following error` 是水平ZDT的软件运动保护：超过2RPM，或位置跟随误差超限；当前定位指令为1RPM。它不是B13本身的错误。界面现在区分具体触发值；锁存此历史故障后，只读回读若连续3次确认两轴已静止、无驱动报警、使能状态稳定且仍使能轴已跟上保留目标，可独立进行固定喷嘴试喷。运动与自动瞄准仍需恢复，不会清故障、改零位或自动使能。

## 图像比例与识别范围

默认1:1显示，完整画面和2×仍可选择，比例选择会保存。1:1只是显示比例；识别始终使用完整单眼1280×1088画面，再按模型要求等比缩放并补边到640×640。拖动画面或切换显示比例不会改变检测范围。完整画面模式已取消滚动条与缩放之间的反馈，并合并重复布局更新，避免反复改写尺寸造成跳动。

### 已具备正式瞄准条件时

1. 打开“视觉与瞄准”，点击“开启火场识别”，确认车已停稳。
2. 等稳定火焰编号出现，点击目标编号。编号表示跟踪目标；短暂 YOLO 框不一定已经成为可选择目标。
3. 点击“一键瞄准 · 喷水 · 关水”，核对确认框中的编号并确认。
4. 流程依次执行双轴瞄准、实际角度到位检查、有限短喷、实际关水确认。每轮最多一次喷水；是否真正灭火仍需现场确认。
5. 目标身份在确认期间或队列等待期间变化，会拒绝本次操作。网页不自动重发。

文本入口：`对选定火焰执行一轮灭火`。语音走相同动作，但喷水相关语音仍需独立转写复核。随时可用“停止喷水”停止。

不需要每次先到空载电机调试页点击两个使能。正式云台由正式控制节点接管串口；同时开启空载调试和正式控制会产生串口竞争。正式控制仍需本次开机实际零位以及真实角度反馈。

## 区域搜索

- `去C区域搜索火焰`：沿原路线搜索；确认合适火焰后停车，将本批画面两侧的稳定目标逐个前后对中并停留1秒，再返回原暂停位置继续。
- `在C区域搜寻火源并执行灭火`：确认合适火源后停车，保持底盘静止，将当前画面中的稳定火焰排队。每团经 3 个新曝光、1 秒停稳观察后，由固定双目三维点与相机到喷嘴几何计算云台角度，实际到位后有限短喷并确认关水。全部已确认目标都完成才继续原路线；不再先移动车轮将每团火焰放到图像中线，也不另规划靠近路线。

当前连续路线采用停稳云台灭火，不要求旧轮式靠近配置中的地图配准、水程范围、车体净空和运动曝光对时全部验收。这些旧配置不被改成已验收，也不伪造世界坐标。实际喷水仍由固定相机三维瞄准门核对当前深度、几何配置、双轴编码器与停稳、目标身份和 B13 反馈。若已确认目标丢失或无法瞄准/喷射，本任务保持停车并报告未完成，不跳过后自动开走。

地图面板显示本次区域任务统计：

| 字段 | 含义 |
|---|---|
| 当前可见 | 当前新鲜画面内有效、可选择火焰数量 |
| 累计跟踪记录 | 按跟踪会话和目标 ID 去重后的记录数；重新进画面可能生成新 ID |
| 已定位火源 | 仅旧世界地图定位流程有已验收坐标时统计；当前停稳云台模式不编造地图位置 |
| 完成短喷 | 已收到实际喷水再关水证据的轮数，不等于已灭火数量 |
| 本批已喷 | 目标身份与本轮编号一致，且有 B13 高→低及解除喷水授权证据的目标数 |
| 未确认候选 | 尚未达到新鲜多帧稳定确认的候选，不算已喷或已灭火 |

所有稳定目标都会被统计，不只统计自动选择的那一个。任务结束保留统计；新区域任务开始重置。连接过期时显示历史统计，不把旧画面说成当前数量。不能仅凭目标 ID 推断全场真实火焰总数。

新的停车触发要求：实际导航运行后的至少4个新曝光，稳定跨度至少0.45秒，置信度至少0.90，完整检测框离图像边缘至少2%，中心进入画宽20%～80%，框尺寸至少占画宽1.5%和画高2.5%。边缘碎框、规划时的旧图、同帧反复发布不会立即停车。20%～80%只决定何时停车，停稳后仍观察完整画面两侧。只搜索模式按左右位置前后对中，在中线±5%范围内停稳1秒；搜索并灭火模式保持底盘停稳，云台逐团瞄准短喷。队列最多32个，超限会停车报告，不能遗漏后继续。

曾出现X5已经下发微调、FPGA返回`centering_fpga_jog_rejected_1`的问题：旧FPGA把暂停导航微调错误地绑定到另一个手动驱动模式。配套FPGA修复删除该多余条件，仍要求同一导航会话暂停、真实停稳、链路与位姿有效以及B13低电平。必须更新配套FPGA位流，单独更新网页不能解决这个拒绝。

## 双轴与标定设置

“视觉与瞄准 → 双轴与标定设置”显示停稳、真实输出、编码器零位、双目、安装几何、落点和水泵的具体缺项。可打开云台角度控制、导出诊断，进入“安装与标定步骤”。

标定工作台支持测量资料录入、JSON导入、下载草稿及直线几何仿真，详见 [固定相机云台标定操作](固定相机云台标定操作.md)。当前安装采用用户提供的尺寸；相机与几何零位喷嘴朝车身左侧，相机无俯仰和侧倾，使用直线瞄准策略，不要求水流落点补偿表。双目控制精度与轴参考绑定仍需验收，不能把草稿预设当成已实测安装。

相机固定在车身，喷嘴转动不会让画面中的火焰移动到中心。因此正式控制比较的是三维目标所需角度和两个编码器的实际角度，不采用“转喷嘴直到图像居中”的方法。

## 上电与导航清零

人工原地清零 IMU 后，FPGA 保留已设置的地图车头方向，等待清零完成再绑定新的 IMU 零点。地图向左仍为地图向左，不会因 IMU 变为 0° 而变成地图向右。校准期间禁止起步；行驶中清零会停车并使旧参考失效，需要重新确认起点后规划。

拓展 1、拓展 2 的 FPGA 控制页改用纯色背景，其他摄像头显示页保留画面。需烧录本次新 FPGA 文件才能看到。
