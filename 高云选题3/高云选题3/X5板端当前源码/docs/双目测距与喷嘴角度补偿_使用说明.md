# 双目测距与喷嘴角度补偿

2026-10-11：已接入当前高速 YOLO 和 X5 本地云台控制代码。没有修改 YOLO 模型、640×640 网络输入、1280×1088 预览、JPEG 90 或原来的去畸变处理。测距是一个单独的 ROS 2 节点，只取原相机话题，不打开第二个相机驱动。

当前交付配置仍为未标定、模拟执行。软件算式与合成图测试通过，不等于这对实物镜头已经通过距离验收，也不等于水流已经命中。真实基线/外参、同步、喷嘴安装偏移和实测落点仍需测量；没有填猜测的距离或安装角度。

## 整条链怎样运行

```mermaid
flowchart TD
    L[物理左眼 /image_right_raw] --> Y[原高速 YOLO：火焰、消防员、人物]
    L --> S[stereo_depth：同一左帧 + 同步右帧]
    R[物理右眼 /image_left_raw] --> S
    Y --> D[/perception/detections：原时间戳与检测框]
    D --> S
    S --> M[双目标定校正 → SGBM 视差 → 左右一致性与质量检查]
    M --> X[转回原去畸变图坐标：火焰 XYZ、Z 深度、欧氏距离]
    X --> E[/perception/depth_detections]
    E --> A[fire_aim：关联同一个火焰]
    A --> P{有适用的实测水流落点表？}
    P -->|有| W[按距离内插实测落点：已包括安装偏移和水流影响]
    P -->|没有，但喷嘴几何已标定| G[喷嘴原点和方向 + 距离 → 几何瞄准像素]
    P -->|均未标定| C[仅画面中心视觉对准]
    W --> Q[火焰与参考点的偏航、俯仰角差]
    G --> Q
    C --> Q
    Q --> V[比例控制、限幅 → Mission 仲裁 → X5 硬件 PWM]
    V --> L
    W --> H[还需稳定锁定、停车、许可及水泵联锁，才成为喷水候选]
```

两种补偿是**互斥的绝对瞄准点**，不能把几何偏移再加到实测落点上。几何补偿可用于云台对准，单靠它不能授权喷水。

## 距离与角度到底怎么算

双目先把左右原始图校正到同一极线。视差 `d = u_left - u_right`，理想水平双目有 `Z = f * B / d`；程序使用标定得到的 Q 矩阵恢复三维点。它还检查左右匹配一致性、图像纹理、有效视差比例和深度离散程度，拒绝负视差、弱纹理、混合深度和越界目标。

当前 YOLO 图是单目去畸变图，双目算法用的是另一张双目校正图，二者像素不能直接混用。程序把检测框范围投影到双目校正图筛选有效深度，再用 `R1.T` 把三维点转回物理左眼坐标。X 向右、Y 向下、Z 向前，单位米。输出的 `depth_m` 是 Z；补偿采用 `range = sqrt(X² + Y² + Z²)`，不是把 Z 当成斜距。

壁纸目标目前取框内可靠深度的中值，并沿检测框中心射线重建目标点。因此它是火焰所在局部墙面的估计，假设该小区域近似正对镜头；不是火焰根部分割，也不是倾斜墙面的平面拟合。明显斜视、框跨到背景、反光或缺少纹理时，应调整观察位，不能把没有通过质量检查的数字当精确距离。

喷嘴几何标定给出原点 `t` 和方向 `a = R_camera_from_nozzle[:,2]`。喷嘴与相机一起转动时，先求射线 `p = t + s*a` 与目标距离球面 `|p| = range` 的正向交点，再把 p 投影为图中的参考像素。这样近距离偏移较大，远距离偏移较小，并能包含喷嘴安装角偏差。代码没有假设水流初速度，因而不声称补偿了重力下坠。

火焰像素与参考像素分别转为视线，计算偏航和俯仰角差，再用原来的限速闭环调整舵机。每次移动后重新取图、重新测距；没有依靠一次角度计算后盲目转到终点。舵机记录的是指令角度，仍不是实测角度反馈。

## 配置文件

| 文件 | 填什么 |
|---|---|
| `config/stereo.template.json` | 双目 K1/D1/K2/D2、R/T、单眼尺寸及标定编号。T 用米，左眼必须是物理左眼。可用现有 `tools/calibrate_stereo.py` 从棋盘格同步照片求解。 |
| `config/stereo_runtime.template.json` | 左右话题、图像旋转、同步/眼序/实测距离验收状态。默认 `enabled=false`；全部验收且有 `verification_id` 才计算米制距离。 |
| `config/gs130w_intrinsics_20261010.json` | 目前预览去畸变使用的镜头快照。运行时要求它的左右 K/D 与实测双目标定一致，且实际 CameraInfo 的 K 与输出几何一致；否则拒绝关联。 |
| `config/nozzle.template.json` | 喷嘴出水口相对物理左镜头光心的 XYZ、喷嘴到相机的旋转矩阵、标定编号、固定安装编号、可用距离范围。默认未标定。 |
| `config/landing.corrected.template.json` | 同一安装方式、泵档位、当前图像坐标中的实测水流落点。优先用于最终瞄准，不能只改 `landing_calibrated=true`。 |

复制模板为自己的 `.measured.json` 文件再填写，保留原模板。若实测内参与当前 EEPROM 快照不同，应据实生成新的镜头配置，并在视觉程序和补偿程序中使用同一份文件；新的 CameraInfo 会使旧的喷嘴像素标定与落点表失效，需要重新确认。切勿只改 frame 名称来绕过坐标检查。

运行参数默认在消防模式才做测距，目标测距频率 5 Hz、OpenCV 2 线程；这不是实测性能保证。相机/YOLO 保持各自速率。深度计算不排长队，只处理最新检测，但必须找到该检测**精确时间戳对应的左图**。右图必须唯一匹配且时间差不超过 12 ms；时间接近本身不能证明曝光已同步。超过 0.5 秒的结果丢弃，深度失败不沿用上一次距离。停用或未标定时不订阅两路原始图，也不运行 SGBM。

## 在 X5 上怎么启动和查看

先保持当前相机、YOLO 和 8086 预览正常运行。以下命令在 VS Code 的 **X5 远程终端**执行：

```bash
cd /root/rescue/ros2_ws
bash tools/run_local_fire_control.sh
```

这会同时启动 `stereo_depth、fire_aim、mission、fpga_bridge、local_actuator`，默认 UART 和执行器均模拟输出，舵机追踪未启用、泵关闭。不要与另一套 Mission/执行器控制器重复运行。没有真实 FPGA 停车反馈和消防任务状态时，不会自动进入灭火动作。

另一个终端查看状态：

```bash
cd /root/rescue/ros2_ws
export ROS_DOMAIN_ID=0 ROS_LOCALHOST_ONLY=0
source env.sh
ros2 topic echo /stereo/depth_status
```

默认 `gate=disabled` 是配置未验收的正常状态。`computed` 表示完成匹配，但仍要看每个目标的 `depth_valid`；`matching_right_frame_missing` 是对应右帧缺失；`camera_geometry_rejected` 是标定/画面几何不一致。

按 Ctrl+C 结束 echo 后，可分别查看：

```bash
ros2 topic echo /perception/depth_detections
ros2 topic echo /fire/proposal
```

不要同时在同一终端粘贴两条持续 echo 命令。第一条看 `depth_valid、position_m、depth_m、depth_reason`；第二条看 `target_range_m、range_source、compensation_kind、geometry_compensation、aim.angle_error_deg、servo_plan`。

| `compensation_kind` | 意义 |
|---|---|
| `image_alignment_only` | 当前只有图像对准，不能认定水流对准。 |
| `rigid_nozzle_geometry` | 距离、喷嘴平移及安装角已参与计算，未补偿实测水流影响。 |
| `measured_water_landing` | 使用同距离范围内的实测落点，几何补偿不会重复叠加。 |
| `target_association_unverified` | 当前火焰与距离无法唯一对应，暂停本帧修正与锁定。 |

完成真实标定后，可以用下列参数选择文件，仍保留执行器模拟输出先看角度：

```bash
bash tools/run_local_fire_control.sh \
  stereo_calibration:=/root/rescue/ros2_ws/config/stereo.measured.json \
  stereo_runtime:=/root/rescue/ros2_ws/config/stereo_runtime.measured.json \
  lens_intrinsics:=/root/rescue/ros2_ws/config/lens.measured.json \
  nozzle_calibration:=/root/rescue/ros2_ws/config/nozzle.measured.json \
  landing_calibration:=/root/rescue/ros2_ws/config/landing.measured.json
```

这些 `.measured.json` 文件当前没有伪造生成。实际 IO 的调试与喷水许可仍遵循 [X5 本地云台与水泵说明](X5本地云台与水泵_接线与联调.md)。在还没有双目验收时，可继续用此前的 `fixed_observation_range_m` 和 `fixed_observation_verified` 显式指定实测固定观察位；输出会标为 `range_is_assumption=true`，不会冒充双目实测。

## 代码学习顺序

1. `depth_frame_join.py`：如何对应同一帧，为什么不能随便拿“最新右图”。
2. `stereo.py` 和 `stereo_detection_geometry.py`：视差、三维恢复和图像坐标转换。
3. `stereo_depth_node.py`：ROS 订阅、测距线程、过期拒绝与结果发布。
4. `nozzle_geometry.py`：喷嘴偏移、安装角、参考像素计算。
5. `fire_aim_node.py`：补偿优先级、目标关联、多帧锁定及角度提案。
6. `mission_node.py`、`local_actuator_node.py`：任务仲裁与实际 PWM/GPIO 接口。

软件测试与板上联调记录保存在 `logs/stereo_compensation_20261011/`。合成标定和测试图只用于隔离 ROS 域 83，不会写入实物标定文件或正式相机话题。
