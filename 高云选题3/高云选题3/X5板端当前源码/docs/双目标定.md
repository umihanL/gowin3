# 双目测距怎样接入这辆小车

已实现的是 OpenCV 双目标定、左右图整流、StereoSGBM 视差、左右一致性检查和目标区域三维坐标。它不需要重新训练 YOLO：YOLO 在**整流后的左目图**找到火焰，深度模块在相同像素坐标内取可靠的表面距离。

输出坐标系为 `rectified_left_optical`，X 向画面右，Y 向下，Z 向前，单位米；`depth_m` 是 Z 深度，不是机器人到目标的欧氏直线距离。它也不是地图坐标。若要转换到车身、喷嘴或地图坐标，仍要测量相机安装外参，并结合实际云台姿态；发送给舵机的角度不能直接冒充已测量的姿态。

## 先做实测标定

`config/stereo.template.json` 中的参数故意留空且 `calibrated=false`。GS130W 型号本身不能给出你这台相机的真实焦距、畸变和基线。程序在没有标定时仍可做图像识别，但拒绝输出米制深度。

1. 打印平整棋盘格并固定在硬板上，测量**打印后的**单格边长。例：内角点 9 列、6 行意味着黑白方格 10 列、7 行；测量的是方格边长，输入米，例如 20 mm 输入 `0.020`。不要直接采用打印文件标称尺寸。
2. 用最终工作的单眼分辨率、镜头焦距和采集模式拍摄左右同步图。若相机输出左右拼接帧，从**同一原始帧**分离两眼；若驱动输出两个流，应使用硬件同步或真实采集时间戳做配对。连续两次 `read()` 后人为赋相同时间戳并不构成同步。
3. 拍 30～50 对，至少保留 20 对能够检出全部内角点的图像。让棋盘覆盖画面中间、上下左右边缘；改变距离、水平转角和俯仰角，不要全部平行摆在画面中心。双目必须同时看见完整棋盘，画面清晰、不过曝，板面保持平直。
4. 保存到 `capture/left/0001.png` 和 `capture/right/0001.png`；两侧文件名主干必须一一对应。标定工具不会从文件名推断同步关系。确认拍摄同步后运行下面的命令。

在 X5 的工作区根目录运行（数字是棋盘示例，必须换成自己的测量值）：

```bash
python3 tools/calibrate_stereo.py \
  --left capture/left --right capture/right \
  --cols 9 --rows 6 --square-m 0.020 \
  --synchronized-capture-confirmed \
  --output config/stereo.measured.json
```

工具用每第五对作为留出验证，其余图拟合左右内参和相对外参。它检查：

| 项目 | 默认通过条件 |
| --- | --- |
| 左右内参、双目标定的训练重投影 RMS | 每项不超过 1.0 像素 |
| 留出图整流后的左右角点纵向误差 | 平均不超过 0.75 像素，95% 分位不超过 1.5 像素 |
| 留出图利用左目棋盘姿态预测两眼的重投影误差 | 平均不超过 1.5 像素 |
| 训练角点覆盖范围 | 每个眼睛的水平、竖直范围各达到图像尺寸的 45% |
| 外参 | 合法旋转矩阵；横向双目；左/右顺序正确；米制基线合理 |

这些是软件初始质量门槛，并不是 GS130W 精度保证。未通过时工具退出码为 2，结果文件会写 `calibrated=false` 和失败原因；应重新拍摄、检查角点数量/左右顺序/棋盘尺寸，不要为了运行而手动改成 true。工具中覆盖范围检查不能完全替代人工检查视角多样性。

## 在线处理和拒绝条件

处理顺序为：左右原图 → 使用实测参数整流 → 左目检测 → 两眼 SGBM → 匹配一致性及纹理检查 → 在检测框内部稳健统计表面 XYZ。

默认对以下情况返回无效或抛出明确错误，不会用上一次距离伪装当前测量：

- 相机尚未标定，或图像分辨率与标定不一致。
- 左右采集时间差超过 20 ms；此阈值应根据实际车速、云台转速收紧。
- 非正视差、超出搜索范围、左右对应点不一致、位于无效整流区域。
- 图案缺少纹理，或者对应右目被遮挡。
- 测距不在配置范围内，或者检测框被裁切。
- 框内可靠像素比例或数量不足，或者包含差异很大的多层深度。

默认搜索 96 个视差、匹配窗口 5 像素，距离允许 0.15～5.0 m；这是计算参数，不能理解成每个距离都有可靠精度。近处视差可能超范围，远处视差只有几像素时误差迅速增大。增加 `num_disparities`（必须是 16 的倍数）会增加 CPU 负载。应使用实际主观察区间 0.4～1.0 m 的打印壁纸验证，在 X5 上测耗时后确定深度发布频率。双目匹配目前运行在 CPU，不是 BPU。

对于居民楼上的平面火焰壁纸，测到的是壁纸所在的墙面距离，符合该项目的靶面测距用途。真实火焰透明、跳动、左右形态不一致，不能把这个算法的壁纸测距效果直接当成真实火焰测距效果。框内中值也可能偏向背景；喷射前应保证火焰靶面占据框内主要区域，并检查匹配质量。

## 代码接口

```python
import json
from rescue_vision.stereo import StereoDepth, CalibrationError, FrameError

calibration = json.load(open('config/stereo.measured.json', encoding='utf-8'))
stereo = StereoDepth(calibration, {'num_disparities': 96})

if stereo.calibrated:
    left_rect, right_rect = stereo.rectify(left_bgr, right_bgr)
    # 必须在 left_rect 上检测；框坐标与下面的深度图一致。
    depth = stereo.compute(left_rect, right_rect, stamp_delta_s=left_stamp-right_stamp)
    point = stereo.sample_bbox(depth, [x1, y1, x2, y2])
    # point['valid'] 为 true 才能使用 point['xyz_m'] / point['depth_m']。
else:
    # 可以继续在原始左目做识别，并明确发布 depth_valid=false。
    pass
```

`StereoResult` 包含 `disparity_px`、`valid_mask`、`xyz_m`、`gray_left`、`frame_id`、`reason`。无效深度图像素为 NaN。`sample_bbox()` 返回适合 JSON/ROS 消息转换的字典，至少包含 `valid`、`xyz_m`、`depth_m`、`frame_id`、`valid_ratio`、`samples` 和 `reason`；其中有效深度的离散程度由 `depth_mad_m` 给出。

相机图像一旦改成整流输出，其 `CameraInfo` 也必须使用对应的整流投影矩阵 `P1`，不能继续把原始畸变内参交给瞄准模块。检测框、深度图和瞄准像素必须属于同一帧、同一眼、同一种整流状态。

## 实物验收

在 0.4、0.6、0.8、1.0 m 放置真实打印壁纸，用卷尺记录靶面到相机的距离，测试正面、斜面、明暗条件；保存测距误差、有效率和耗时。再用云台低速移动确认帧同步和时间延迟。只有此后才把有效深度交给已标定的喷嘴落点表；图像锁定与准确喷水命中仍是两项不同的验收指标。

自动测试采用明确标注为测试用的合成参数验证几何和拒绝逻辑，未使用真实 GS130W 参数，不能代表相机实测精度。
