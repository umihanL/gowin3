## 当前已经做了什么

打开[8086单画面识别网页](http://192.168.127.10:8086/)查看当前效果。现在默认：

| 配置 | 行为 |
|---|---|
| `fire_only=true` | 仅输出火焰候选，暂时不输出消防员、人物 |
| `process_fps=10.0` | 当前输入频率上限，不保证实际每秒处理10帧 |
| `lens_enabled=true` | 默认启用单眼去畸变；设为false可关闭做画面对照 |
| `lens_intrinsics` | 使用工作区`config/gs130w_intrinsics_20261010.json`中的候选K/D |
| `lens_alpha=0.0` | 单眼去畸变时优先减少黑边，画面边缘会裁切 |
| 左眼输出 | BGR、640×544、`undistorted_left_optical` |
| 双目距离 | 仍未验收；`depth=uncalibrated`，不能用于精确喷水定位 |

BIN文件仍是`wallpaper_yolo11n_3class_bayese_640_nv12.bin`。模型仍计算三类分数；程序先按原有规则选出最高分类分数，再保留`class_id=0`的火焰。因此不会因为打开火焰模式，就把最高分为人物的目标重新叫作火焰。只启用一类不等于BPU计算量降到原来的三分之一。

CPU后处理已改为先筛选候选，再对入选框解码DFL；默认三类结果已用随机输出对比旧流程验证一致。还减少了不必要的图像消息构造与搬运。实际加速幅度必须看板端整条链路的统计。

## “去畸变”与“双目融合”有什么区别

广角镜头可能把画面边缘的直线拍弯。当前处理使用EEPROM来源的K（内参）和D（畸变参数），以`R=I`做**单眼画面矫正**，再输出640×544参考图。参数已接入，但眼别对应关系、当前安装/旋转模式下的实际几何效果仍须用真实图案核验。

单眼去畸变不等于左右眼极线校正，也不等于完成测距或相机到喷嘴的标定。当前消息内容是：

| `/vision/frame`字段 | 当前格式 | 使用范围 |
|---|---|---|
| `left` | 去畸变BGR，640×544 | YOLO和网页显示使用的参考图 |
| `right` | 原始NV12，1280×1088 | 保留原眼图；需经过正确的后续双目流程才能测距 |

**左右图当前编码、尺寸和几何处理不同，不可直接当成同尺寸整流图对做视差。** 检测框坐标属于640×544矫正画面，不再是原始1280×1088像素坐标；转换到瞄准角度时要使用这张输出图对应的有效内参，且还需喷嘴外参、机构误差与实测落点校验。

8000官方网页仍显示两幅原始图，所以它仍可能看起来有广角畸变。这不说明8086去畸变未运行。检查8086中的“镜头与距离”状态，并用门框、方格纸或打印直线比较矫正前后；若仍弯曲、方向异常或裁切不合理，应先核对候选K/D与实际镜头和旋转的对应关系，不把视觉上“变直一点”当成精度证明。

## 页面上的速度数字分别是什么意思

| 指标 | 包含什么 | 不能怎样解释 |
|---|---|---|
| 单次BPU推理，ms | 模型前向计算阶段的耗时 | 不能用`1000/ms`直接宣称整车视觉帧率 |
| 完整算法处理率，帧/秒 | 实际算法处理与输出的速率；受图像解码、去畸变、预处理、BPU、后处理和发布影响 | 不等于官方相机原图帧率 |
| 顶部识别画面更新率，帧/秒 | 预览后端收到并匹配同一帧图像和检测结果的速率 | 不等于显示器刷新率，也不保证浏览器每帧都绘制 |
| 图像年龄，秒 | 当前显示图距离拍摄时间的间隔 | 不能只看帧率而忽略它；高帧率仍可能滞后 |

页面会显示分阶段耗时用于判断瓶颈。当前配置输入上限是10.0，当前实测约7帧/秒；配置上限不能当成实测速率。测量结果在`logs/fire_lens_20261010/summary.json`，采样明细为同目录`before.json`与`after_final.json`。不把旧三类原图配置或桌面微基准的速度当成本轮结果。

## 当前程序怎样管理

现在无需再启动。底层相机和8000原图网页仍在用户终端前台运行，本轮没有重启它们。算法与检测网页由两项临时服务运行：

```bash
systemctl status rescue-mipi-vision rescue-detection-preview --no-pager
journalctl -u rescue-mipi-vision -u rescue-detection-preview -n 60 --no-pager
```

这些命令在**X5远程终端**执行。普通非root账号在`systemctl`前加`sudo`。两项服务均未配置开机自启；停止算法只停止识别，不关闭底层相机，也不停止8086网页进程，网页会随后提示没有新结果。

需要修改模式时，先停止当前算法服务，再选择下列一种前台命令：

```bash
cd /root/rescue/ros2_ws
systemctl stop rescue-mipi-vision
```

默认仅火焰＋去畸变：

```bash
bash tools/run_mipi_vision.sh
```

恢复三类输出，保留去畸变：

```bash
bash tools/run_mipi_vision.sh fire_only:=false
```

每次更换命令前先Ctrl+C停止上一套前台算法。`run_mipi_vision.sh`有`flock`锁，如果提示已运行，请检查服务或前台终端，不要绕过锁启动第二套。

只为了对比画面，关闭单眼去畸变、保持仅火焰：

```bash
bash tools/run_mipi_vision.sh lens_enabled:=false
```

`lens_enabled:=false`使算法忽略去畸变参数路径，无须修改或清空JSON文件。矫正前后画面视场和坐标不同，比较时重点看同一真实直线形状，不能直接比较同一个像素坐标。对照结束后Ctrl+C，再运行不带覆盖参数的默认命令，即恢复去畸变。

如只想关闭检测网页而保留算法：

```bash
systemctl stop rescue-detection-preview
```

重启X5后的校时、相机及网页手动启动顺序，见[单画面YOLO预览说明](单画面YOLO预览_使用说明.md)。前台程序运行期间要保持对应终端；未来如需开机自启，应单独配置正式服务，不依赖这次临时服务。

## 接下来怎样确认有效

1. 先看网页模式是否为“仅火焰”、镜头处理是否报告已去畸变，再对照真实门框或方格纸观察边缘直线。
2. 用地图里实际打印的火焰壁纸，依次在约0.4米、0.7米、1.0米观察框，随后改正面/斜角和明暗；距离用尺量，不使用当前无效深度。
3. 记录无火焰楼面或普通背景中的误检。百分数只是模型置信度，不是该场景实测准确率。
4. 看图像年龄、完整算法率和匹配画面率是否持续稳定；连接中断时留在网页上的是历史帧，不代表当前场景。

本轮只进行相机取图、火焰识别和只读显示，没有控制底盘、云台或水泵。准确灭火仍需真实双目与喷嘴标定后再接控制闭环。
