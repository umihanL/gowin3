# GS130W单目去畸变：实读证据与代码接口

记录日期：2026-10-10。此模块只做单眼桶形畸变校正，仍未验收双目米制深度、EEPROM与实物眼别的对应关系或精密瞄准。

## 实读证据

本次从运行中的驱动订阅`/image_left_raw/camera_info`和`/image_right_raw/camera_info`，保存完整K、D、R、P、尺寸、ROI、时间戳，以及驱动命令、boot ID到`config/gs130w_intrinsics_20261010.json`。没有填写猜测系数，也没有使用安装包中的示例标定。

同一boot的原始日志`/root/.ros/log/mipi_cam_7667_946685153293.log`第31～75行确认：EEPROM总线4、标识SZYGSJKJ、`cal_type=0`、`angle=1`、`d_num=8`，左右标定尺寸均为1280×1088。实际左右fx分别约666.0804和666.4528，与实读CameraInfo一致。

官方`tros_2.5.2`代码中，`angle=1`对应标定图像旋转90°。当前驱动也是`rotation=90`、`cal_rotation=90`、1280×1088、`gdc_enable=False`，因此直接按这个横向图像空间使用K/D，不能再把K/D额外旋转90°。

- [EEPROM解析源码](https://github.com/D-Robotics/hobot_mipi_cam/blob/tros_2.5.2/src/hobot_mipi_calibration.cpp)：按头部模型区分equidistant与plumb_bob，按angle读取标定方向。
- [X5采集与GDC源码](https://github.com/D-Robotics/hobot_mipi_cam/blob/tros_2.5.2/src/x5/hobot_mipi_cap_iml.cpp)：GDC关闭时将EEPROM两组CameraInfo直接送出，按固定索引对应左右话题。
- [CameraInfo生成源码](https://github.com/D-Robotics/hobot_mipi_cam/blob/tros_2.5.2/src/hobot_mipi_cam.cpp)：右眼R/P包含相对左眼的外参；不是本模块直接采用的单眼整流矩阵。

实读`distortion_model=plumb_bob`且D有8项，对应OpenCV rational模型顺序`k1,k2,p1,p2,k3,k4,k5,k6`，使用普通`cv2.initUndistortRectifyMap`。视觉上看起来像鱼眼，不代表可以切换到只有4个系数的`cv2.fisheye`接口。某些系数较大的正数也不是直接判错依据：rational模型包含分子和分母。

## 眼别和坐标边界

用户遮住物理左镜头时网页下半变暗，所以默认逻辑角色映射为`left → /image_right_raw`、`right → /image_left_raw`。模块允许调用方显式修改映射，不依据话题名字猜物理左右。

官方驱动把EEPROM第0/1组参数直接按话题索引绑定，尚未通过实物标定板验证哪组参数属于哪只镜头。当前保持图像与该话题CameraInfo配套，标记`candidate_eeprom_eye_assignment_unverified`；这可以用于候选校正画面，但不能宣称精准瞄准标定完成。

单目校正使用**R=I**，不套用右眼CameraInfo的R/P。EEPROM外参T约`(-80.002136, 0.172327, 0.043501)`，与80毫米基线一致；不能把原P中的数值直接按米解释。双目测距仍需单独校验单位、眼别、整流和同步。

## 调用接口

```python
from rescue_vision.lens_correction import LensCorrector

corrector = LensCorrector.from_json(
    "/root/rescue/ros2_ws/config/gs130w_intrinsics_20261010.json",
    alpha=0.0,
    role_to_source={"left": "/image_right_raw", "right": "/image_left_raw"},
)

# 这里传入的是已由调用方选出的物理左图，必须仍为1280×1088。
result = corrector.correct(
    bgr_image,
    role="left",
    output_size=(640, 544),
    input_metadata={"rotation": 90.0, "source_topic": "/image_right_raw"},
)
undistorted_bgr = result.image
newK = result.camera_matrix  # result.newK是同一接口的别名
metadata = result.metadata
```

初始化只读取JSON，重映射表在该眼第一次调用时创建并缓存。每帧只做remap；alpha=0优先裁掉无效边缘，因此视场可能变窄。原始输入分辨率、图像旋转或源话题不匹配时抛出ValueError，不静默缩放错误参数。

如果上游已经通过官方GDC或其他算法去畸变，调用方必须声明并提供**上游实际输出图的K**：

```python
result = corrector.correct(
    already_corrected_bgr, role="left",
    already_rectified=True,
    rectified_camera_matrix=upstream_K,
)
```

此时不再去畸变。缺少实际K会拒绝处理，以免将原图K冒充校正后的K。输入metadata中的`rectified=True`、`lens_correction_applied=True`、`gdc_enable=True`，或快照驱动参数中的GDC开启状态，也会触发该保护。这里不自动查询上游实时参数，调用方需要提供准确状态。

YOLO看到校正后的640×544图，模型再letterbox到640×640。检测框解除letterbox后属于**校正图像像素空间**，必须与`newK`配套，不能与原始1280×1088的框混用。若只校正左眼、右眼保留原始NV12，整个StereoPair仍须`rectified=false`。候选检测画面可以用`undistorted_left_optical`标识，不输出已验证的米制瞄准坐标。

官方`gdc_enable=True`不是本模块的必要条件：它可能同时执行双目整流，并依赖眼别与外参。在当前软件校正入口使用时保持GDC关闭；以后切换硬件GDC必须关闭软件重复校正并重新验收坐标。

测试入口为`tests/test_lens_correction.py`，本地8项unittest已通过，覆盖投影生成的弯曲直线校正、两眼映射、重映射表缓存、错误分辨率/旋转/畸变模型拒绝、上游已校正保护与本机真实参数加载。视觉校正效果和精密标定准确度仍需实物直线/棋盘格验证。
