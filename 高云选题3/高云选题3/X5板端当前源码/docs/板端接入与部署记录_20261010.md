# RDK X5 接入与实际部署记录

更新：2026-10-10。网线、SSH、VS Code 和主工程板端部署已完成，可以开始远程开发。

## 现在怎么打开

- 双击本目录 `打开VSCode远程工程.cmd`，在 X5 上编辑 `/root/rescue/ros2_ws`。
- 双击 `打开上位机软件预览.cmd`，启动板端软件预览与 SSH 转发；电脑浏览器打开 http://127.0.0.1:18088/。
- 逐步操作见 `VSCode与板端开发_一步一步.md`，已同步到板上 `ros2_ws/docs/`。
- 页面令牌由板端生成，在远程终端执行 `cat ~/.local/state/rescue_robot/dashboard.token`，复制到页面“访问令牌”输入框。不要把实际令牌提交到仓库。

交付时已启动 `rescue-preview.service` 临时后台预览；没有设置开机自启。要使用 VS Code 的前台启动任务，先执行 `bash tools/preview_service.sh stop`，避免两套程序占用同一端口。

## 板端验证结果

证据位于主工程 `ros2_ws/reports/board_20261010/` 和 `ros2_ws/logs/board_20261010/`，本机与板端各有一份。

| 检查 | 结果与范围 |
|---|---|
| 编译 | `rescue_interfaces`、`rescue_vision` 两个包成功；开发入口脚本再次构建成功 |
| 核心逻辑 | 85 项单元测试通过 |
| 全部节点 | 10 个节点稳定运行，认证 HTTP 返回实际 ROS 状态 |
| 红绿灯 / UART | 17 项通过；真实 ROS 与 pyserial，Linux PTY 模拟 FPGA，合成 LED 图 |
| 导航 / UART | 28 项通过；1.84 米模拟路段回执、继续/停车、错误命令和遥测过期处理 |
| 网页 / ROS | 16 项通过；命令、路线返回、令牌、重复命令和时间戳处理 |
| YOLO BPU | 真实 X5 BPU 载入 BIN 并执行；输入输出与合同一致，检出火焰/消防员/人物 |
| OpenCV / ROS | 实际 BGR8 图片与 ROS 图像消息往返通过 |
| 楼牌 OCR | CPU 实际识别合成图的“08幸福楼”“消防救援”，匹配楼栋 H |
| Vosk 语音 | 6 条已打包的合成中文录音全部完成预期语义解析，包含否定指令拒绝 |

性能仅为样例检查：预热后 3 次 BPU forward 为 27.7～28.2 ms；CPU 后处理约 54～60 ms，另有预处理。**不能把单独 BPU 耗时当成整车 FPS。** 全图 CPU OCR 本次约 4.26 秒；6 条离线语音逐条解码约 4.3～7.0 秒。本次部分计算与构建并行，未进行持续实时性能评估。

导航首次测试失败的原因已定位并修复：测试重启 interaction 时同步等待进程退出，暂停了模拟 MCU 遥测。导航正确拒绝了无有效定位的执行请求。现在等待退出时继续发送遥测，并新增间隔断言；实测最大间隔 0.0513 秒，28 项复测通过。产品控制阈值未放宽，原失败证据保留。

## 仍要在实物上完成

YOLO `.bin` 可在 BPU 运行，但原先量化精度门槛未全部通过；这里没有把运行成功改写为实拍精度达标。水泵实控尚未实现。
