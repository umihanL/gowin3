# 原始数据与融合数据复现

普通训练直接使用 `dataset/data.yaml`，无需 Blender，也不用重新生成图片。本页只用于审计和未来重新制作数据；先安装 `requirements-data.txt`。Blender 渲染使用其自带 Python。

`source_data/v6_ground_floor/` 冻结新版 GLB、纹理、源标注、240 对计划和渲染工具。不能用后续再次改过的活动地图冒充本版源文件；工具在写输出前会检查场景、计划和源标注哈希。

在本训练工程根目录用 PowerShell 执行以下命令可验证/继续缺失的同版本渲染；已有完整图像会按来源检查后跳过：

```powershell
& 'D:/仿真工具/Blender/blender.exe' -b --python source_data/v6_ground_floor/tools/render_stereo_blender.py -- --glb source_data/v6_ground_floor/scene/community_fire_rescue_v6.glb --plan source_data/v6_ground_floor/render_plan.json --annotations source_data/v6_ground_floor/source_annotations/annotations.json --output source_data/v6_ground_floor/rendered --resume
```

重新打包到一个新的输出目录，而非覆盖已冻结的来源包：

```powershell
python tools/package_dataset.py --input source_data/v6_ground_floor/render_plan.json --rendered source_data/v6_ground_floor/rendered --output source_data/v6_ground_floor/packaged_rebuild
```

本次 `source_data/v6_ground_floor/packaged` 由同一脚本从原图与 mask 生成，其中 train 才产生 `_a01.jpg`。`source_data/v5_legacy/packaged` 是旧 V1 原包的按字节快照；其原始 manifest 已校验，不要手改后再称为原数据。

从两份冻结包重新融合到新目录：

```powershell
python tools/merge_datasets.py --output dataset_rebuild
python tools/validate_merged_dataset.py --dataset dataset_rebuild --output dataset_rebuild/independent_validation.json
python tools/build_merged_review.py --dataset dataset_rebuild
```

`merge_datasets.py` 对已有输出目录拒绝覆盖，会先写 `<输出名>_building` 临时目录，所有生成步骤完成后才改名。若中途失败，先查看错误原因和目录内容，不要手动改 hash 来绕过检查。重新生成、合并图片不包含任何模型训练。

V5 快照的工具/模型来源见其 `snapshot.json`、`scene_snapshot/manifest.json`；V6 冻结与派生依据见 `source_manifest.json`、`source_derivation_proof.json`。首次搬移完整工程后运行 `train.py --check-only` 检查所有活动路径。
