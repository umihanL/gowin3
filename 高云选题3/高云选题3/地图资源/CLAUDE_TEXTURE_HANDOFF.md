## 交接目标

请为当前的社区消防救援迷宫场景绘制一套可直接替换的视觉贴图。主场景文件名为：

```text
community_fire_rescue_maze.blend
```

场景构建脚本为：

```text
build_rescue_maze.py
```

这是一个用于小车视角、视觉识别和导航流程演示的参数化模拟场景。场地尺寸、楼体尺寸、道路宽度和障碍物布局均为工程假设，不代表赛方指定尺寸，也不应在贴图、文件名或说明中写成官方赛场复刻。

贴图的用途是增强合成视觉数据和人工检查效果。它们不改变碰撞体、导航地图、雷达可见几何或消防控制逻辑，也不构成真实火焰、水流或建筑物的物理仿真。

## 输出位置与文件名

请将最终 PNG 放在场景工程下的相对目录：

```text
assets/textures/
```

文件名必须保持以下拼写和大小写，以便 Blender 脚本按固定路径加载：

| 文件 | 用途 | 规格 |
| --- | --- | --- |
| `facade_calm/people/fire.png` | 居民楼正立面、门窗、可辨识行人和火焰的合成立面 | 3072 x 1536，2:1，正面平视构图 |
| `asphalt.png` | 沥青路面 | 1024 x 1024，可平铺 |
| `road_straight/crosswalk.png` | 直路和路口/斑马线表面 | 2048 x 2048，可平铺或按 UV 对齐 |
| `parking_surface.png` | 停车区或硬质场地表面 | 2048 x 1024 |
| `parking_sign/construction_sign.png` | 停车标识、施工提示标识 | 1024 x 1024 |
| `barrier_stripes.png` | 路障、围挡或警戒条纹 | 2048 x 256，可沿长度方向平铺 |

如果当前代理实际生成的是扁平文件名，请在提交前按上表建立对应目录并移动/复制到固定路径；场景脚本不应依赖临时文件名。原画版本必须保留在独立的版本目录或带版本后缀的备份文件中，不能只保留经过压缩或裁切的替换版。

## 绘制要求

### 楼体正立面

- `facade_calm/people/fire.png` 必须是近似正面、无明显透视收缩的楼体立面。
- 门窗、墙体分格和楼层线要保持水平、垂直，方便相机前视识别和贴图对齐。
- 立面中应有少量但清晰的居民/行人形象，以及独立可辨认的火焰目标；人物和火焰不能被窗框、文字或阴影切断。
- 火焰应放在可作为检测目标的平面位置，避免做成整幅红色噪声或严重透明的光斑。火焰纹理是视觉目标标记，不代表真实燃烧模拟。
- 门窗、行人和火焰的比例要与场景楼体高度一致，不能用近景海报式大头像填满整面墙。
- 不要加入需要阅读才能理解的长文本。若必须出现标牌文字，使用简短、无歧义的中文或英文，逐字检查，避免错别字、镜像字和乱码。

### 道路与地面

- `asphalt.png` 应使用低对比度、无方向性的沥青颗粒和少量磨损，四边可无缝拼接。
- `road_straight/crosswalk.png` 的车道边缘、中心线和斑马线要有明确方向；斑马线不能在平铺后出现断裂或错位。
- `parking_surface.png` 的标线应保持与 UV 方向一致，不能在连续停车位之间出现明显跳变。
- 地面贴图必须保持哑光、低反射，避免大面积高光导致相机曝光和深度估计不稳定。

### 标识与障碍物

- `parking_sign/construction_sign.png` 和 `barrier_stripes.png` 要有清楚的形状边界和颜色分区，便于目标检测与人工辨识。
- 施工标牌的斜纹方向必须在同一套资产中统一；禁止出现左右方向随机翻转。
- 标识贴图只描述视觉外观，不改变对应障碍物的碰撞尺寸、导航膨胀半径或激光雷达模型。

## 统一视觉风格

整体采用克制、清晰的合成数据风格：中等饱和度、哑光材质、适度环境遮蔽和干净边缘。楼体、路面、标识和障碍物应看起来属于同一套场景，不能混用照片写实、卡通插画和强烈霓虹风格。

请避免：

- 过度模糊、重度暗角、强烈镜头光晕和无法识别的深色区域；
- 透视角度与平面正视要求冲突的楼面照片；
- 把道路箭头、斑马线或门窗画到纹理边缘之外，导致 UV 平铺时接缝明显；
- 细小且不可读的文字、品牌 Logo、现实地点名称或可能误导为真实赛方标志的内容；
- 贴图中直接绘制碰撞边界、导航路径、坐标轴或调试标签。

保留足够的颜色和亮度差异，让楼体与路面、火焰与背景、警戒条纹与障碍物能够在正面相机视角下区分。纹理不应以单一色块覆盖所有结构。

## 技术契约

- 格式：PNG；色彩空间：sRGB；颜色通道按实际需要使用 RGB 或 RGBA。
- 不使用带有不可追踪外部链接的程序化材质，不把贴图打包成只在个人电脑上可访问的绝对路径。
- 文件路径使用工程相对路径；不要在 Blender 材质中写入 `C:\Users\...`、临时目录或下载缓存路径。
- 保留原始源文件（例如 PSD、Krita、SVG 或无损 PNG）和最终 PNG 的版本关系；最终 PNG 不能覆盖唯一原稿。
- 若使用透明背景，明确说明透明区域的预乘/非预乘处理，避免 Blender 中出现黑边。
- 贴图压缩后仍应能看清窗框、行人、火焰、斑马线和警戒条纹；不能为了减小体积而把 3072 x 1536 的立面降到低于约定尺寸。

## 替换流程

当前实际地面是 `assets/road_wallpaper.png`：4608×3072，整幅覆盖12×8米，北在图像上方。其道路、车位和斑马线位置必须跟 `rescue_maze_config.json` 一致；`road_straight.png` 等为额外可复用素材，不是当前整图地面的主贴图。施工牌箭头必须向右，指向东侧绕行路线。打印大幅实体墙纸时，按实际板材尺寸另行提高分辨率并核对有效DPI。

1. 先保留现有材质与原画版本，复制到带日期或版本号的备份目录。
2. 将新 PNG 放入 `assets/textures/` 的固定相对路径。
3. 在 `build_rescue_maze.py` 中重新运行材质绑定和场景生成；不要手工只改 `.blend` 后跳过脚本，以免下次构建丢失贴图。
4. 用 Blender 打开或后台执行生成后的 `community_fire_rescue_maze.blend`，确认所有 Image Texture 节点均指向工程相对路径。
5. 执行 Blender 的打包贴图操作，将场景和所需图片重新写入交付副本；同时保留可审计的外部 PNG 目录。
6. 若还要生成 GLB、Webots 世界或其他运行时包，必须从重新生成的场景导出，并检查导出包内纹理引用没有指向旧版本。

### 视觉检查

- [ ] 楼体正面无不合理透视，门窗分格稳定。
- [ ] 行人和火焰在小车前视画面中可以辨识，火焰不会被墙体或窗框遮挡。

### 光照与相机检查

- [ ] 至少用白天均匀光、低照度/阴影光两组灯光测试。
- [ ] 在小车前视、低位近景和俯视检查，不出现整片过曝或纯黑区域。
- [ ] 火焰颜色在不同曝光下仍与墙面和窗户可区分，但不会产生大面积光晕吞没边缘。
- [ ] 贴图不会遮盖或修改薄墙、门洞、路障和其他碰撞几何。
- [ ] 生成的占据栅格、导航点和传感器模型与换贴图前保持一致。
